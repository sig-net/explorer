## Goal

The running system has been attacked from outside, as a stranger on the internet would, by
someone who did not write it, and every finding is marked `blocking` or `advisory`. You change
no file. You read the code and run it, not the builders' reports: do not open anything under
`agent-work/reports/`.

## Read first

- `../../../architecture.md`, sections 1, 7, 8 and 10, and `../../../decisions.md`, whole.
- `packages/backend/src/http/`, `src/composition/`, `src/main.ts`, `src/config/`,
  `src/services/`, and `packages/ui/src/components/contexts/`, `src/lib/explorer-backend/`.

## Work

Start a backend to attack: the local Postgres, a scratch database you create and drop yourself,
`migrate`, then `start` with both roles and preprod configured from the secret, set in the
process's environment only (never in a file, never printed). Let it index a few thousand blocks.
Pipe everything you capture through `redact`. Then, in this order:

1. Secrets. Capture every reply of every route and the whole log of the run, at `LOG_LEVEL=debug`
   too. Search both for the project id's VALUE (compare by `grep -c -F -f` against the secret
   read into a file descriptor, so it is never printed), for `project_id`, and for the host of
   the EVM endpoint. Make the indexer fail (an unreachable URL in a second run) and search the
   replies and the log again: errors are where a URL escapes.
2. Verdicts (D02): does any reply say that something is valid, verified or authentic?
3. The open proxy: can `getMidnightTransaction` be made to fetch a hash that is not in the
   events table? Can `getEthereumTransactionOutput` be made to call the node without bound
   (many hashes, many chain ids)? Is a miss ever stored?
4. Input: a page size of zero, negative, and far above the maximum. A search fragment of
   100000 characters, one holding `%`, `_` and a backslash (do the wildcards match as
   themselves?), one holding a quote. A page token that is random bytes, and one from another
   network. A body of 10MB. Each must be a refusal with a message, never a 500, a hang or a
   wrong page.
5. Errors: make a service throw (stop Postgres's connection to the scratch database). Does the
   caller get anything but the generic reply? Does the process survive?
6. CORS: a preflight and a request from an origin that is not configured, from `null`, and
   with no origin. `/healthz` must not depend on the database.
7. The process: SIGTERM during a range leaves the checkpoint consistent (start it again and
   compare with a rebuild). Both roles in one process and split across two processes behave
   the same. The listener's bind address is what the configuration says.
8. The UI: build it, then search `packages/ui/dist` for an indexer's host, for
   `debug_traceTransaction`, for a fixture of the fakes. With no backend URL the page says so
   and shows no invented request.

File your report FIRST, then run the exit check. In `FINDINGS`, each finding is one line
starting `FINDING <n> (blocking): ` or `FINDING <n> (advisory): `, with the file and line and
what you ran. `blocking` means: the code does other than the design says, loses data, leaks a
secret, or a check passes without the work. Everything else is `advisory`. With no finding at
all, write the line `NO FINDINGS`. Add one line `ATTACKED: ` listing which of the eight items
you completed. Stop your backend and drop your scratch database before you report.
