## Goal

`node packages/backend/src/main.ts` starts the backend from its environment: it refuses a
database whose schema is not the shipped one, runs an ingester per configured network when its
roles include `ingest`, and serves the four services over HTTP when they include `serve`. It
stops cleanly on a signal.

## Work

1. `http/http-host.ts`: `createHttpHost({ adaptors, corsAllowedOrigins, logger })` returns a
   Fastify instance. It registers every route `mountRoutes` returns as a POST with a JSON
   body, `GET /healthz` answering 200 with `{ ok: true }`, and `@fastify/cors` for exactly the
   configured origins. A reply is a value with status 200, also for `ok: false`. An exception
   from a service is logged in full and answered `{ ok: false, error: 'internal error' }`: no
   message of the exception reaches the caller. A body that is not JSON and a route that does
   not exist get Fastify's own 400 and 404. Set a body size limit as a named constant.
2. `composition/create-backend.ts`: `createBackend(config, logger)` builds, in dependency
   order: the pool and database, the repositories and unit of work, per configured network the
   indexer chain source and its facts for the network service, the EVM trace sources, the four
   services, their adaptors, then, by role, the ingesters and the host. It returns
   `{ start(), stop() }`. Nothing here reads the environment.
3. `start()`: read the schema state FIRST. `mismatch` and `empty` both refuse to start, with a
   message that names the command to run and erases nothing. Then start the ingesters (each
   network in its own loop, one network's failure or halt not stopping another) and the
   listener on `HTTP_PORT`, bound to `0.0.0.0` only when a variable says so, else `127.0.0.1`.
4. `commands/`: a table from command name to function, with `start` as the default and
   `migrate`, which applies the migration to an EMPTY database and refuses any other state.
   `main.ts` loads `.env` beside the package when it exists (`process.loadEnvFile`), parses the
   configuration, builds the logger, runs the named command, and on SIGINT or SIGTERM calls
   `stop()`: abort the ingesters, close the listener, end the pool. A configuration error
   prints its message and exits 1. Add the scripts `start` and `migrate` to `package.json`.
5. Tests. The host through Fastify's `inject`, over fakes from `@explorer/api/fakes`: every
   route answers what the fake holds. A preflight from an allowed origin is allowed and from
   another is not. A throwing service gives the generic reply and the recording logger holds
   the cause. No reply and no log line of the whole suite contains `project_id` or `://` of a
   configured endpoint. The composition on a scratch database with the fake chain source: role
   `serve` alone starts no ingester, role `ingest` alone opens no listener, and `mismatch` and
   `empty` refuse.
6. `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/05.1.sh` proves the files exist, and starts the real process: it migrates a scratch
database, starts `main.ts` with the role `serve` and no network configured, gets 200 from
`/healthz` and four networks that are not configured from `/network/listNetworks`, sees the
process refuse an empty database, and stops it. It cannot prove an ingester runs in the process:
05.3 does that on preprod.
