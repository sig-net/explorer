## Goal

A test anyone can run again proves the task's one promise on a real chain: started from an empty
database, the backend catches up on preprod from block 3386746 and then holds exactly the events
an independent read of the indexer gives, with rows equal to a rebuild, and a browser reads them
through the HTTP API from another origin. Gates G20 and G21 are answered with numbers.

## Read first

- The stage's `stage.md`, beside `steps/`: gates G20 and G21. G20 failing stops the task.
- `../../../architecture.md`, section 5. `../../../decisions.md`: the defaults chosen from
  G04, G05 and G07.
- `packages/backend/src/main.ts`, `src/composition/create-backend.ts`,
  `src/ingester/ingester.ts` (the default settings), `src/testing/scratch-database.ts`.
- `packages/api/src/http.ts` (the clients) and `packages/api/src/sign-request/derive-sign-request.ts`.

## Work

1. `packages/backend/e2e/preprod.e2e.test.ts`, skipped unless `MIDNIGHT_PREPROD_INDEXER_URL`
   is set, with a timeout that fits a catch-up. On a migrated scratch database it builds the
   real backend for preprod alone, with both roles, on a free port, with the test's origin
   allowed, and waits until the checkpoint is within the safety margin of the head, logging
   blocks a minute and requests made.
2. Then, with the checkpoint's block as the upper bound, read both contracts again through the
   SDK's `signetEventSourceFromIndexer`, which shares no code with the chain source's checks.
   Assert: the same number of events. For each, the same block height, block hash, transaction
   hash, name and payload, in the same order within a block. No stored event the SDK did not
   return. This is G20's first half.
3. G20's second half: for every request id, the stored row equals `deriveSignRequest` over
   that request's stored events. And through the HTTP client: walking every page of
   `listSignRequests` returns each row once, and `getSignRequest` of the oldest, the newest
   and one request with several events returns the stored events.
4. `getMidnightTransaction` of the oldest event's transaction returns the bytes the indexer
   returns for that hash, and a second call does not reach the indexer (count the chain
   source's calls). A hash that no event carries is refused.
5. Stop the backend, start it again on the same database: it resumes from the checkpoint, and
   after two turns steps 2 and 3 still hold.
6. `packages/ui/e2e/backend.e2e.test.ts`, skipped unless `VITE_E2E_BACKEND_URL` is set, run in
   vitest's browser mode: the real HTTP clients, from Chromium, call `listNetworks` and
   `listSignRequests` on that URL. This is the proof that CORS lets the UI's origin in. Add a
   second case that a request from an origin the backend does not allow is refused by the
   browser.
7. A root script `e2e:preprod` runs it all in order: Postgres up, the backend test, then a
   backend left running on a scratch database for the UI's test, then the teardown. It takes
   the secret from the environment and prints no URL.
8. G21: from the run, record the catch-up's duration, its request count, and the requests a
   day of the steady state. If the defaults do not fit the allowance stage 01 measured, change
   the default constants in `ingester.ts`, each with the gate and the number it comes from,
   and run again.
9. Look once at the query plan of a search by fragment on the caught-up database
   (`explain analyze`) and say in the report whether the trigram index is used.
10. `yarn lint`, `yarn build`, `yarn check`, then `yarn e2e:preprod` with the secret set as
    the `probes` pack's command sets it. Commit. In `FINDINGS`, give under lines starting
    `G20:` and `G21:` the verdict (`holds` or `fails`) and the numbers: events compared,
    requests, catch-up seconds, requests made.

## Done when

`checks/05.3.sh` proves both test files and the script exist, the report holds the two gate
lines, all checks pass, and `yarn e2e:preprod` passes when run again here with the secret. It
cannot prove the indexer itself is complete: section 5 says what the guarantee is and is not.
