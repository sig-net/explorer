## Goal

`probes/node-typescript/` is a toy of the planned layout (a `backend` package importing a `lib`
package's TypeScript source and the SDK) with a script that runs it under plain Node, here and in
the image's Node 24.18. `probes/findings/node-typescript.json` answers gate G10.

## Read first

- `../stage.md` (the stage's file, beside `steps/`): the row G10 of the gate table.
- `../../../architecture.md`, section 2 only: the packages and who imports whom.
- `tsconfig.app.json:1-27`: the compiler options the app is held to (`erasableSyntaxOnly`,
  `verbatimModuleSyntax`, `allowImportingTsExtensions`).

## Work

1. Run `yarn install --immutable` at the repository root. The toy installs NOTHING of its own
   and has no lockfile: it resolves `@sig-net/midnight` from the root's `node_modules` by
   Node's upward search.
2. Make `probes/node-typescript/packages/lib/` with a `package.json` (`"name": "@probe/lib"`,
   `"type": "module"`, `"private": true`, `"exports": { ".": "./src/index.ts" }`) and a
   `src/index.ts` that re-exports from a second file through a relative import ending in `.ts`.
   Use only erasable TypeScript: an interface, a generic function, `import type`, `satisfies`,
   a constant object with a derived literal union.
3. Make `packages/backend/` the same way (`@probe/backend`) with `src/main.ts`, which imports
   from `@probe/lib` and from `@sig-net/midnight`, and prints one line `ok <what>` for each of:
   a value and a type imported from `@probe/lib`, `getSignerContractAddress(MidnightNetwork.
   Preprod)`, `normaliseSecp256k1PublicKey(getMpcRootPublicKey(MidnightNetwork.Preprod))`,
   and `tryDecodeSignetEvent({ name: 'x', payload: new Uint8Array(256) }) === undefined`.
4. Write `probes/node-typescript/run.sh`. It links the packages the way Yarn's `node-modules`
   linker links workspaces: `node_modules/@probe/lib` and `node_modules/@probe/backend` as
   RELATIVE symlinks to `../../packages/<name>` (git ignores `node_modules` at any depth). Then
   it runs `node packages/backend/src/main.ts` twice: with the local Node, and with
   `docker run --rm -v "<repository root>":/repo:ro -w /repo/probes/node-typescript
   node:24.18.0-bookworm-slim node packages/backend/src/main.ts`. It captures each run's exit
   code and standard error, and with `--verdicts` prints one line `{"G10":"holds"}` or
   `{"G10":"fails"}`: `holds` only when both runs exit 0 and print all five `ok` lines.
5. Also try, and record in the evidence without letting them change the verdict: whether
   either Node prints a warning about type stripping, and what Node says to a file holding an
   `enum` (put that file where `main.ts` does not import it).
6. Numbers to write: `local_node_major`, `image_node_major`, `local_exit_code`,
   `image_exit_code`, `warnings_printed` (0 or 1). `head` is 0: this probe asks no indexer.
   The probe's name is `node-typescript`.
7. Run `yarn format`, then `yarn lint`, `yarn format:check` and `yarn typecheck` at the root.
   If the root's lint or format check trips over the toy's TypeScript, fix the toy, never the
   root's configuration. Commit everything except `node_modules`.

## Done when

`checks/01.8.sh` proves the findings file has gate G10 with evidence and the five numbers, and
that `run.sh --verdicts`, run again with Docker, gives the same verdict. It cannot prove that
Yarn links workspaces exactly as `run.sh` does: stage 02 proves that with the real workspaces.
