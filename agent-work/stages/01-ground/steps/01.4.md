## Goal

`probes/contract-events-paging.mjs` puts gates G01 and G02 to the preprod indexer and measures
what G07 needs about `limit`. Its answers are in `probes/findings/contract-events-paging.json`.

## Read first

- `../stage.md` (the stage's file, beside `steps/`): the rows G01, G02 and G07 of the gate table.
- `node_modules/@sig-net/midnight/dist/signet-contract-events.js:108-241`: the query and the
  paging the SDK uses today.

## Work

1. Run `yarn install --immutable`. Write the probe as the pack says. Take the two contract
   addresses from the SDK. Use your own query, selecting `__typename id maxId transactionId
   contractAddress transaction { id hash block { height hash timestamp } }`, with NO `types`
   filter, so that every kind of event is seen.
2. Read the whole history of each contract from block 3386746 to the head, 100 rows a page.
   Record the row count of each contract and how many rows are not `MiscContractEvent`.
3. G01. `holds` only when all of these are seen: `id` strictly ascends on every page and from
   one page to the next. Along ascending `id`, the block height never falls. In the two
   contracts' rows merged by `id`, the block height never falls either. Inside one block,
   `transactionId` never falls along ascending `id`. Say in the evidence how many rows and
   how many blocks holding two or more rows were tested: with no such block the last test is
   `not-observed` and the gate's evidence says so.
4. G02. Pick a block B that holds a row and whose neighbours B-1 and B+1 hold none of that
   contract's rows. `holds` only when `fromBlock: B, toBlock: B` returns B's rows,
   `fromBlock: B+1` leaves them out and `toBlock: B-1` leaves them out.
5. For G07, on the contract with the most rows: ask with `limit` omitted, then 1, 100, 500,
   1000 and 5000, and record how many rows come back each time, and what an `offset` beyond
   the last row returns. Numbers to write: `rows_signer`, `rows_responder`, `rows_not_misc`,
   `default_limit`, `max_limit_honoured` (the largest limit that returned exactly that many
   rows, or the row count of the history when the history is smaller than every limit that
   worked), `max_rows_in_one_block`, `blocks_with_several_rows`.
6. Support `--verdicts` for G01 and G02. Write the findings file, run `yarn format`, then
   `yarn lint` and `yarn format:check`. Commit both files.

## Done when

`checks/01.4.sh` proves the findings file has the gates G01 and G02 with a verdict and evidence,
the seven numbers, and that running the probe again gives the same two verdicts. It cannot prove
the tests inside the probe are the ones written above: the orchestrator reads the probe's four
G01 tests.
