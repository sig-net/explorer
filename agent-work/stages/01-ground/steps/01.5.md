## Goal

`probes/head-consistency.mjs` watches the preprod indexer's head for at least 20 minutes and
answers gates G03, G04 and G05. Its answers are in `probes/findings/head-consistency.json`. The
no-gaps guarantee of the design rests on these three more than on anything else.

## Read first

- `../stage.md` (the stage's file, beside `steps/`): the rows G03, G04 and G05 of the gate table.
- `../../../architecture.md`, section 5 only: the loop these gates protect.

## Work

1. Before any code, find out from the indexer's own source whether it indexes finalised blocks
   only or the best chain: the public repository `midnightntwrk/midnight-indexer`, read with
   `gh` or over HTTPS, never cloned into this repository. Look for where the chain indexer
   subscribes to the node. Spend at most twenty tool calls on it. Quote the file, the line and
   the commit in your report, and say that the version Blockfrost runs is not known. If you do
   not find it, say so and go on: the observation stands alone.
2. Run `yarn install --immutable`. Write the probe as the pack says. Everything below is code
   in the probe, nothing is done by hand, and every `contractEvents` read pages to its end.
3. Choosing what to watch, at the start of a run: the Signet contracts emit a few events a day,
   too few. Read the last 300 blocks' `transactions { contractActions { address } }`, count
   calls by address, and watch the two busiest addresses whose `contractEvents` are not empty,
   beside the two Signet contracts. With none, widen once to 3000 blocks, then go on with the
   Signet contracts alone. The addresses watched go in the evidence.
4. The loop, for `--seconds N` (default 1500). `H0` is the first head. Every 2 seconds read
   the head. On each new head H, at once: read the hash of H, and read the watched contracts'
   events with `fromBlock: H-20, toBlock: H`. Remember, for every event id, the head it was
   FIRST seen at, and for every height every hash seen.
5. When the loop ends at head `H1`: read again the hash of every height seen, and read the
   watched contracts' events once more over the whole of `H0+1` to `H1`.
   - Only events in blocks ABOVE `H0` count: an event already there when the run began shows
     nothing. `events_first_seen` is their number.
   - Lag of such an event = the head it was first seen at minus its block height. An event
     the final read holds and no loop read ever held has lag `H1` minus its height.
   - `events_disappeared` = events a loop read held that the final read does not.
   - A replaced block = a height that answered two hashes at any time. Its depth = the head
     when the second hash was seen minus the height.
6. G03, in the same run: pick a closed range ending at least 50 blocks below `H0` that holds
   at least 30 events of one watched contract (else the Signet signer's whole history up to
   `H0-50`), and walk it by `offset` with `limit: 10` at the start, the middle and the end of
   the run. `walk_pages` is the pages of ONE walk.
7. Verdicts, strictly:
   - G03: `holds` with three identical walks of at least 3 pages each. `fails` on any
     difference. It is never `not-observed`: the signer's history is always there to walk.
   - G04: `holds` only with `events_first_seen` of at least 20, a largest lag of 0 and none
     disappeared. `fails` with any lag above 0 or any disappeared. Otherwise `not-observed`.
   - G05: `holds` only with at least 200 heads, no replaced block, AND a source reading from
     item 1 that says finalised blocks only. `fails` with any replaced block. Otherwise
     `not-observed`.
8. Numbers: `observation_seconds` (the loop alone), `heads_seen`, `events_first_seen`,
   `events_disappeared`, `max_event_lag_blocks`, `replaced_blocks`, `max_replacement_depth`,
   `walk_pages`, `head_interval_p50_ms`, `head_interval_max_ms`. All zero or above.
9. `--verdicts` prints the three verdicts and writes no file. With `--seconds 90` it must run
   the whole of items 3 to 7 and end within four minutes: the exit check runs exactly that,
   and so do you, FIRST, before the long run.
10. Run it in full, in the background as the pack says. Write the findings file, run
    `yarn format`, then `yarn lint` and `yarn format:check`. Commit both files. In `FINDINGS`,
    say what `SAFETY_MARGIN`, `REREAD_BLOCKS` and `POLL_INTERVAL` you would default to, and why.

## Done when

`checks/01.5.sh` proves the findings file has the three gates and ten numbers, that the run
lasted at least 1200 seconds over at least 150 heads, that every verdict agrees with the numbers
beside it, and that the probe itself runs: a 90 second run ends and prints three verdicts. It
does not repeat the long run, and it cannot prove the source reading: the orchestrator checks
the quoted file and line.
