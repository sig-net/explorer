## Goal

`probes/chain-lookups.mjs` answers gates G06, G08 and G09: whether the preprod indexer gives a
past block's hash by height, an old transaction's raw bytes by hash, and a clean "does not exist"
for a contract below its deployment block. Its answers are in `probes/findings/chain-lookups.json`.

## Read first

- `../stage.md` (the stage's file, beside `steps/`): the rows G06, G08 and G09 of the gate table.
- `src/lib/midnight/sign-bidirectional-transaction-loader.ts:9-48`: the raw transaction query
  the UI sends today.

## Work

1. Run `yarn install --immutable`. Write the probe as the pack says, with the two contract
   addresses from the SDK.
2. G06. Ask `block(offset: { height }) { height hash parent { hash } timestamp }` for 30
   heights: 0, 1, 3386745, 3386746, the head, and 25 spread evenly between 1 and the head.
   Time each call. `holds` only when every height at or below the head answers a block of that
   height, and for 10 pairs of neighbours the upper block's `parent.hash` equals the lower
   block's `hash`, and `block(offset: { hash })` of 5 of them answers the same height. Record
   what a height above the head answers (null, or which error), in the evidence.
3. G08. Take the transaction hash of the OLDEST event of the signer (first row of
   `contractEvents` from block 3386746) and of the newest. `holds` only when
   `transactions(offset: { hash }) { hash raw }` answers both with a non-empty hex `raw`. Record
   how many transactions one hash answers, the byte length of each `raw`, and what a hash of 64
   zeros answers.
4. G09. For each contract, find its deployment block D by bisection on
   `contract(address, offset: { height }) { address }` between 3386000 and the head, and compare
   with 3386746 (signer) and 3386749 (responder). `holds` only when, for both contracts, height
   D answers the contract and height D-1 answers `null` with no `errors` entry. Record the exact
   answer at D-1 in the evidence, and what an address of 64 zeros answers at the head. Also
   record whether `contractEvents(filter: { contractAddress, toBlock: D-1 }, limit: 1)` is
   empty: it is the fallback's query.
5. Numbers to write: `block_lookup_p50_ms`, `block_lookup_max_ms`, `raw_oldest_bytes`,
   `raw_newest_bytes`, `transactions_per_hash`, `signer_deploy_block`, `responder_deploy_block`.
6. Support `--verdicts` for the three gates. Write the findings file, run `yarn format`, then
   `yarn lint` and `yarn format:check`. Commit both files.

## Done when

`checks/01.6.sh` proves the findings file has the three gates with evidence and the seven
numbers, and that running the probe again gives the same three verdicts. It cannot prove the
bisection is right: the orchestrator compares the two deployment blocks with the numbers above.
