## Goal

`@sig-net/explorer-lib` exports the domain modules that the backend and the api package will need beside the UI, the UI imports them from there, and no copy stays in the UI.

## Read first

- `packages/ui/src/lib/midnight/contract-address.ts`, `signet-events.ts`, `sign-bidirectional-lifecycle.ts`, `network.ts:13-18` and `:344-350` (the network set and its guard), and their tests and fixtures.

## Work

1. Census first: for each export of those four modules, list who imports it (`grep -rn` over `packages/ui/src`). Put the census in your report.
2. Move to `packages/lib/src/midnight/`, with their tests:
   - `contract-address.ts` whole.
   - `signet-events.ts` whole, with one change: add `StoredSignetMiscEvent`, which is `IndexedSignetMiscEvent` without `maxId` and `transactionId` (no code reads either: `grep -rn 'maxId\|transactionId' packages/ui/src` hits tests and fixtures alone), and make it the `source` type of `SignetContractEvent` and the parameter type of `decodeSignetContractEvent`. An `IndexedSignetMiscEvent` is assignable to it, so the UI's event store compiles unchanged.
   - From `sign-bidirectional-lifecycle.ts`: the `SignBidirectionalLifecycle` type and `aggregateSignBidirectionalLifecycles`, as `sign-bidirectional-lifecycle.ts`. The search, caller and duration helpers stay in the UI's file, which imports the type from lib.
   - From `network.ts`: `MIDNIGHT_NETWORKS` and `isMidnightNetwork`, as `midnight-networks.ts`. Everything that reads the environment stays in the UI.
   - The fixtures those tests and the UI's tests share (`sign-bidirectional-event.fixture.ts`, `respond-bidirectional-event.fixture.ts`, `sign-bidirectional-lifecycle.fixture.ts`): move those that only import moved modules, and export them from a second entry `@sig-net/explorer-lib/testing` (add it to the package's `exports`).
3. `packages/lib/src/index.ts` exports the moved modules. Nothing in `packages/lib` may read `import.meta.env`, `window`, `process` or a `@/` alias, or import `luxon`.
4. Update every import in the UI. The mover pays: `grep -rn` for each old module path and leave no hit.
5. The moved tests run in lib's `node` environment. A test that needs a browser stays in the UI with what it tests.

## Done when

`checks/02.3.sh` proves the four modules are in lib and gone from the UI, lib reads no browser or Node global, Node imports lib's exports, and the repository checks pass. It cannot prove the census is complete.
