## Goal

`@sig-net/explorer-lib` exports the domain modules that the backend and the api package will need beside the UI, the UI imports them from there, and no copy stays in the UI.

## Read first

- `packages/ui/src/lib/midnight/contract-address.ts`, `signet-events.ts`, `sign-bidirectional-lifecycle.ts`, `network.ts:13-18` and `:342-346` (the network set and its guard), their tests, and `sign-bidirectional-lifecycle.fixture.ts`.

## Work

1. Census first: for each export of those four modules, list who imports it (`grep -rn` over `packages/ui/src`). Put the census in your report.
2. Move to `packages/lib/src/midnight/`:
   - `contract-address.ts` whole, with its test.
   - `signet-events.ts` whole, with its test and one change: add `StoredSignetMiscEvent`, which is `IndexedSignetMiscEvent` without `maxId` and `transactionId` (no code reads either: `grep -rn 'maxId\|transactionId' packages/ui/src` hits tests and fixtures alone), and use it wherever the module names `IndexedSignetMiscEvent`: the type argument of `DecodedSignetEvent`, both `source` fields and the parameter of `decodeSignetContractEvent`. An `IndexedSignetMiscEvent` is assignable to it, so the UI's event store compiles unchanged.
   - From `sign-bidirectional-lifecycle.ts`: the `SignBidirectionalLifecycle` type and `aggregateSignBidirectionalLifecycles` with the private types and `firstSource` they use, as `sign-bidirectional-lifecycle.ts`, with `StoredSignetMiscEvent` in place of `IndexedSignetMiscEvent`. The duration, event count, search and caller helpers stay in the UI's file, which imports the type from lib and keeps `luxon`.
   - Its test splits. The four tests of the aggregation go to lib: "events group by declared request id, newest lifecycle first", "repeated emissions under one request id are all kept, in emission order", "a response with no request still forms a lifecycle", "events that did not decode join no lifecycle". The three of the helpers stay in the UI: "duration runs from the first request to the first attestation", "search matches a fragment of the request id or of a caller address", "the callers are the distinct addresses named, and a lifecycle is called by any it names".
   - From `network.ts`: `MIDNIGHT_NETWORKS`, `MIDNIGHT_NETWORK_VALUES` and `isMidnightNetwork`, as `midnight-networks.ts`. Everything that reads the environment stays in the UI, with `network.test.ts`.
   - `sign-bidirectional-lifecycle.fixture.ts`, which tests on both sides use. Add `packages/lib/src/testing.ts`, which exports it, and make the package's `exports` a map: `"."` stays `./src/index.ts`, `"./testing"` is `./src/testing.ts` (D32). The two event fixtures (`sign-bidirectional-event.fixture.ts`, `respond-bidirectional-event.fixture.ts`) stay in the UI: only UI tests import them.
3. lib has no `luxon` (adding it would change `yarn.lock`, which is outside your scope). In the files that move, `DateTime.fromISO(x).toJSDate()` becomes `new Date(x)`, and `LIFECYCLE_FIXTURE_START` becomes a `Date` to which the fixture adds seconds as milliseconds.
4. Node runs lib's sources as they are: every relative import inside `packages/lib` carries its `.ts` extension, and no `@/` alias remains. `packages/lib/src/index.ts` exports the four modules. Nothing in `packages/lib` may read `import.meta.env`, `window` or `process`.
5. Update every import in the UI to `@sig-net/explorer-lib`, or `@sig-net/explorer-lib/testing` for the fixture. The mover pays: `grep -rn` for each old module path and leave no hit. `network.ts` re-exports nothing that moved.
6. The moved tests run in lib's `node` environment. Run the exit check with `agent-work try 02.3`.

## Done when

`agent-work/stages/02-workspace/checks/02.3.sh` proves the four modules and the fixture are in lib and gone from the UI, lib reads no browser or Node global and no `luxon`, the fourteen moved tests pass in lib and the three helper tests in the UI, Node imports both entries of lib, `StoredSignetMiscEvent` has the shape above, and the repository checks pass. It cannot prove the census is complete.
