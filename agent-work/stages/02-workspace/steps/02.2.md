## Goal

`packages/lib`, `packages/api` and `packages/backend` exist as empty, typechecked, tested workspaces, and the lockfile already holds every dependency the later stages add code against. No later step needs to change a manifest to add a dependency.

## Read first

- `packages/ui/package.json`, `packages/ui/tsconfig.app.json`: the compiler options to match.
- `package.json`, `.oxlintrc.json` and `.yarnrc.yml` at the root. The root has no `tsconfig.json` (D30).

## Work

1. Three packages, each private, `"type": "module"`, with `"exports": "./src/index.ts"`, a `tsconfig.json` that includes `src`, with `"module": "esnext"`, `"moduleResolution": "bundler"`, `skipLibCheck` and the UI's strictness options (`strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `allowImportingTsExtensions`, `noEmit`), a `vitest.config.ts` with the `node` environment and `passWithNoTests`, and the scripts `typecheck` (`tsc --noEmit`) and `test` (`vitest run`). Each lists `typescript` and `vitest` in its devDependencies at the UI's ranges: `yarn workspace <name> vitest`, which the exit checks call, finds a binary only through the workspace's own manifest.
   - `@sig-net/explorer-lib`: no DOM and no Node types (`"lib": ["ES2023"]`, `"types": []`), since both runtimes import it. Depends on `@sig-net/midnight` at the UI's exact version.
   - `@sig-net/explorer-api`: depends on `@sig-net/explorer-lib` (`workspace:*`), `@sig-net/midnight`, `zod`, `hono`.
   - `@sig-net/explorer-backend`: Node types. Depends on `@sig-net/explorer-lib`, `@sig-net/explorer-api`, `@sig-net/midnight`, `@midnightntwrk/ledger-v9` at the UI's exact version, `hono`, `@hono/node-server`, `kysely`, `pg`, `zod`. Dev: `@types/pg`, `@types/node`. Scripts also `start` (`node src/main.ts`).
2. Each `src/index.ts` holds one line, `export {}`, until a later step fills it. Write no placeholder function.
3. Add `@sig-net/explorer-lib` and `@sig-net/explorer-api` (`workspace:*`) to `packages/ui/package.json`.
4. Take the newest release of each new dependency that Yarn's 24 hour age gate allows. Give the exact versions in your report.
5. oxlint already lints every package from the root, and the overrides that carry the Tailwind and `only-export-components` rules name `packages/ui` paths. Change `.oxlintrc.json` only if a React or Tailwind rule fires on a file of the three packages.
6. `yarn install`, then the exit check with `agent-work try 02.2`.

## Done when

A scratch `packages/lib` of this shape was prototyped at 2adc538: it typechecked, a type-aware lint rule fired in it with no change to `.oxlintrc.json`, `vitest run` with no test exited 0, and Node resolved it from another workspace.

`agent-work/stages/02-workspace/checks/02.2.sh` proves the three packages exist with their names, exports, scripts and dependencies, that Node resolves each from the backend, that Node runs a TypeScript file importing them, and that the repository checks pass. It cannot prove the versions are the newest allowed.
