## Goal

`packages/backend` exists as `@explorer/backend` with every dependency the backend needs up to
stage 06, a local Postgres from `compose.yaml`, a harness that hands each test file a scratch
database, and a script that proves plain Node runs the package. Its tests run in `yarn check`.

## Read first

- The stage's `stage.md`, beside `steps/`: gate G13.
- `../../../decisions.md`: the verdict of G10, recorded by the orchestrator after stage 01.
- In the demo checkout the `backend-patterns` pack names: `src/lib/db/database.ts:1-20` and
  `compose.yaml:12-29`.

## Work

1. `packages/backend/package.json`: name `@explorer/backend`, private, `"type": "module"`.
   Dependencies: `drizzle-orm`, `pg`, `zod`, `fastify`, `@fastify/cors`, `pino`,
   `@sig-net/midnight` at the UI's exact version. Dev dependencies: `drizzle-kit`, `@types/pg`,
   `@types/node`, `pino-pretty`, `vitest`. Versions as the pack says. If G10 failed on source
   imports, add `tsx` too. Scripts: `typecheck`, `test` (vitest, Node environment),
   `db:up` (`docker compose -p explorer up -d --wait postgres`, run from the root).
2. `packages/backend/tsconfig.json` with the strictness the `layout` pack lists, `"types":
   ["node"]`, `allowImportingTsExtensions`, `noEmit`, and no DOM library. Add the package to
   the root `tsconfig.json` references and to the lint configuration, with the React and
   Tailwind rules still limited to `packages/ui/src`.
3. `compose.yaml` at the root, as the `layout` pack says: service `postgres`, `postgres:18`,
   port `127.0.0.1:${EXPLORER_POSTGRES_PORT:-5433}:5432`, user, password and database
   `explorer`, a named volume on `/var/lib/postgresql`, a `pg_isready` healthcheck.
4. `src/db/database.ts`: `createDatabasePool(connectionString)` and `createDatabase(pool)`, and
   the type `DatabaseExecutor`, shaped as the demo's.
5. `src/testing/scratch-database.ts`: `createScratchDatabase()` connects to the local server
   (from `DB_CONNECTION_STRING`, or the Compose default when unset), creates a database named
   `scratch_<random>`, returns `{ pool, database, connectionString, drop() }`. `drop()` ends the
   pool and drops the database. It applies no migration yet: stage 03 adds that.
6. `src/db/database.test.ts`, using the harness: `select 1` answers. `create extension pg_trgm`
   succeeds. `pg_try_advisory_lock` on one key succeeds on one connection and fails on a second
   until the first releases it. Two scratch databases do not see each other's tables.
7. `scripts/node-runs-source.ts`: imports `createDatabasePool` by a relative `.ts` path and a
   value from `@sig-net/midnight`, and prints `ok`. It must run as
   `node packages/backend/scripts/node-runs-source.ts` with no flag and no build (or through
   `tsx` when G10 said so).
8. `packages/backend/.env.example` with `DB_CONNECTION_STRING` for the local server.
9. `yarn install`, commit the lockfile, then `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/02.2.sh` proves the dependencies are declared, Postgres starts from `compose.yaml`, the
package's tests pass against it inside `yarn check`, the Node script prints `ok` here and in the
`node:24.18.0-bookworm-slim` container, and the UI's build is unchanged. It cannot prove the
harness drops every database it makes: the script lists `scratch_%` databases after the tests
and fails when one is left.
