## Goal

The app lives in `packages/ui` as the package `@explorer/ui`, the root is a workspace root, and
every command, check, build and image works as it did. Nothing about the app's behaviour changes.

## Read first

- `package.json:1-67`, `vite.config.ts:1-85`, `tsconfig.json`, `tsconfig.app.json`,
  `tsconfig.node.json`, `components.json`, `.oxlintrc.json`, `.oxfmtrc.json`
- `Dockerfile:1-34`, `docker/30-explorer-env.sh`, `.claude/launch.json`
- `AGENTS.md`: every path it names moves, and you update each one.

## Work

1. `git mv` into `packages/ui/`: `src`, `public`, `index.html`, `vite.config.ts`,
   `tsconfig.app.json`, `tsconfig.node.json`, `components.json`. Use `git mv` so history follows.
2. `packages/ui/package.json`: name `@explorer/ui`, private, `"type": "module"`, the app's
   dependencies and the dev dependencies only it uses (Vite, React tooling, Tailwind, the
   router plugin, vitest's browser packages, Playwright), and the scripts `dev`, `build`,
   `preview`, `typecheck`, `test`, `test:watch`. Its own `tsconfig.json` references the two
   moved configurations.
3. Root `package.json`: name `explorer`, private, `"workspaces": ["packages/*"]`, the
   `packageManager`, `engines` and `resolutions` it has today, the dev dependencies every
   package shares (`typescript`, `oxlint`, `oxlint-tsgolint`, `oxfmt`,
   `eslint-plugin-better-tailwindcss`), and scripts with the SAME names as today: `dev`,
   `build` and `preview` run the UI's, `typecheck` runs `tsc -b`, `lint`, `format` and
   `format:check` run at the root over everything, `test` runs every package's `test`, and
   `check` keeps its four parts in today's order. Root `tsconfig.json` references `packages/ui`.
4. `.oxlintrc.json` and `.oxfmtrc.json` stay at the root. Re-point every path in them
   (`src/routes/**`, `src/components/ui/**`, the Tailwind entry point, `src/routeTree.gen.ts`)
   at `packages/ui/src/...`. Keep `agent-work` in the formatter's ignore list.
5. `vite.config.ts`: the footer's version still comes from git (the `git` calls work from a
   subfolder). The build's output is `packages/ui/dist`.
6. `Dockerfile`: copy the root manifest, the lockfile, `.yarnrc.yml` AND `packages/ui/package.json`
   before `yarn install --immutable`, build with the root's `yarn build`, and take the site
   from `/app/packages/ui/dist`. `.dockerignore` and `.gitignore` already match `dist` and
   `node_modules` at any depth: check with `git status` after a build, and fix what shows.
7. `.claude/launch.json`: both entries still start the dev server and the Pages preview.
8. The mover pays. `git grep -nE "src/(lib|components|routes|index\.css|routeTree|fonts|vite-env)"`
   outside `packages/ui`, `agent-work` and `probes`: update every hit in `README.md`,
   `AGENTS.md` and the configurations to its new path. Inside `AGENTS.md`, change paths and
   nothing else.
9. Run, in this order: `yarn install` (the lockfile changes: commit it), `yarn lint`,
   `yarn build`, `yarn check`, then `EXPLORER_BASE_PATH=/explorer/ yarn build`. Commit.

## Done when

`checks/02.1.sh` proves the old root folders are gone, the install is frozen, CI's commands and
`yarn check` pass with at least 143 tests, the build under `/explorer/` puts that base in
`index.html`, the two WebAssembly files are the only ones, and no stale `src/` path is left
outside the package. It does not build the image: the stage check does. It cannot prove the app
looks the same: the orchestrator starts `yarn dev` and loads the explorer page once.
