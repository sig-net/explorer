## Goal

The repository root is a yarn workspaces root, and the app lives in `packages/ui` as `@sig-net/explorer-ui`, unchanged in behaviour. `yarn check` and `yarn build` at the root still do what they did.

## Read first

- `package.json`, `vite.config.ts`, `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json`, `components.json`
- `.oxlintrc.json`, `.oxfmtrc.json`, `.dockerignore`, `Dockerfile`, `docker/`
- `README.md` and `AGENTS.md`: both name paths under `src/`.

## Work

1. `git mv` into `packages/ui/`: `src`, `public`, `index.html`, `vite.config.ts`, `components.json`, the three `tsconfig*.json`, `Dockerfile` and `docker/`. Nothing of the app stays at the root. Then write a new root `tsconfig.json` that holds only `"files": []` and a `references` entry for `packages/ui`, which type-aware oxlint needs when it runs from the root.
2. `packages/ui/package.json`: name `@sig-net/explorer-ui`, private, with the app's dependencies and its `dev`, `build`, `preview`, `typecheck` and `test` scripts.
3. Root `package.json`: it keeps its name `explorer`, is private, has `"workspaces": ["packages/*"]`, and keeps `packageManager`, `engines`, `resolutions`, the lint and format tools and `typescript` (which `oxlint-tsgolint` needs, and which the UI also lists). Its scripts: `typecheck`, `test` and `build` run every other workspace that has the script (`yarn workspaces foreach -A --exclude explorer --topological run <script>`: without the exclusion the root would run itself), `lint`, `format` and `format:check` run oxlint and oxfmt once over the whole repository, `dev` and `preview` run the UI's (`.claude/launch.json` calls `yarn preview` at the root), and `check` stays typecheck, lint, format check, test in that order.
4. Point `.oxlintrc.json` (its `overrides` globs, its Tailwind `entryPoint`, its `ignorePatterns`) and `.oxfmtrc.json` at the new paths. Keep `agent-work` ignored in both. `packages/ui/dist` and `packages/ui/src/routeTree.gen.ts` stay ignored: check that the patterns match the nested paths by running `yarn lint` and `yarn format:check` after a build.
5. `packages/ui/Dockerfile` builds from the repository root as its context: one `COPY . .`, then `yarn install --immutable`, then `yarn workspace @sig-net/explorer-ui build`, and it serves `packages/ui/dist`. Copying everything before the install means a package added later needs no edit here. In `.dockerignore`, make `node_modules`, `dist` and `Dockerfile` match at any depth (`**/node_modules`, `**/dist`, `**/Dockerfile`).
6. The mover pays: search the whole repository for every path that moved (`src/`, `public/`, `docker/`, `dist`, `Dockerfile`, `index.html`, `vite.config.ts`, `components.json`, `tsconfig`, `routeTree.gen.ts`) and update each hit in `README.md`, `AGENTS.md` (its paths become `packages/ui/src/...`), `.claude/`, `.vscode/`, `.gitignore`. Do not edit `.github/workflows/**`: list in your report each line there that names a moved path, with the value it needs.
7. `yarn install`, then run the exit check. A build may rewrite the tracked `packages/ui/src/routeTree.gen.ts`: commit it when it changes.

## Done when

`checks/02.1.sh` proves the root is a workspace root with no `src`, the repository checks and the build pass with all 143 tests still run, the build emits the same set of WebAssembly files as before, a build under `/explorer/` succeeds, and the UI image builds. It cannot prove the README still reads true: the final review reads it.
