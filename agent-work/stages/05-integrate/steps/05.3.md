## Goal

Everything a person needs to build, run and operate the explorer once `agent-work/` is removed is in the repository's own documentation, and nothing in it names a thing the task removed. Why it is built so is `DECISIONS.md`, which step 05.6 writes: link to it, do not repeat it.

## Read first

- `README.md`, whole (688 lines): it describes the app as it was before this task. Its headings: `grep -n '^#' README.md`. The docs pack lists its lines that are no longer true, the variables the UI still reads and what the workflows need.
- `agent-work/architecture.md`, the section `## Design`.
- `agent-work/decisions.md`: D11, D12, D14, D22, D41, D51 and D56 to D60.
- `packages/backend/src/config/backend-env.ts:11-110` (every variable and its default), `packages/backend/src/main.ts`, `packages/backend/src/backend.ts`, `packages/backend/Dockerfile`, `packages/backend/compose.yaml`, the `scripts` of `package.json` and of `packages/backend/package.json`.
- `packages/api/src/routes.ts` (the endpoints) and `packages/ui/src/lib/explorer-env.ts` with `packages/ui/src/vite-env.d.ts` (the variables the UI reads).
- `AGENTS.md`, whole.

## Work

1. Root `README.md`, short: what the explorer is (the UI, the backend, PostgreSQL, a paragraph each and how they talk), the four workspaces and what each holds, the requirements, the root scripts, how to run all of it locally against preprod (`yarn db:up`, a `packages/backend/.env.local` with a Blockfrost project id and `EXPLORER_HOST=127.0.0.1`, `yarn dev:backend`, a `packages/ui/.env.local` with `VITE_EXPLORER_API_URL`, `yarn dev:ui`), how to run the tests (the backend's need `EXPLORER_TEST_DATABASE_URL`), the two images, GitHub Pages, and links to the three documents below and to `DECISIONS.md`. Never write a secret's value: the project id is `<your project id>`.
2. `packages/backend/README.md`: every environment variable with its default and what an invalid value does, the endpoints under `/v1`, `/healthz` and `/readyz` with when each answers what (D56), the image (build and run commands), the ingest in plain words (the processed block moves only in the transaction that stores its data), the sync states, what `stopped` means, how it lifts (D51) and how an operator wipes a network (D58), the log lines (D59), how the process stops (D57), and what a Kubernetes deployment must provide: one replica, the variables, the two probes, a PostgreSQL 17 where the backend may create the `pg_trgm` extension, and about 11,000 requests a day per network to Blockfrost at the default poll interval.
3. `packages/ui/README.md`: the app's own reference, moved from the root README and corrected. Keep what is still true (stack, Tailwind, theme, networks, the WebAssembly rule, lifecycles, signature and attestation checks, the local SDK link, routing, tests). Delete or rewrite every passage the docs pack names: the request list is read from the backend 50 at a time with "Load more", search and caller exclusion are answered by the backend and a search under 3 characters is no search (D22, D41), the configuration popover shows the backend's addresses, start block and source URL read only and marks a network the backend does not serve (D11), and the page shows each network's sync state.
4. `AGENTS.md`: correct every path and rule the task made untrue (the file layout rules name `packages/ui` alone: say where backend, api and lib code goes, from the tree as it is). Add under "Boundaries and ownership", in these words where the check reads them: the UI reads Midnight data "from the backend alone", never from an indexer or a node, no response and no log line carries a URL's "query string" or credentials, and a database test fails without `EXPLORER_TEST_DATABASE_URL`, it never skips.
5. Run every command you quote, verbatim, before you write it, and name every path from the tree, never from memory. A command that needs the Blockfrost token takes it from the dev secrets inside the command, so that it never reaches your output. Start containers under names of your own and remove them. The live run of step 05.2 may be using the machine at the same time: a test that times out once is load, run it again alone.
6. `grep -rniE 'blockfrost|indexer|starting block|start block|yarn dev' README.md packages/*/README.md` and read every hit: each must be true of the code as merged.
7. `yarn format`, then the exit check. In your report, under a heading `FOR THE USER`, the exact change each file under `.github/workflows/` needs, read from the files as they are (the docs pack says where to look). You change no workflow file.
