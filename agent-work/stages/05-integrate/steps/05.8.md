## Goal

A PostgreSQL that ends the backend's connections (a restart, a failover) leaves the backend running: it logs the error and the next cycle and the next request use a new connection. Every launch configuration calls a root script that exists.

## Read first

- `packages/backend/src/db/database.ts:13-17`: `openDatabase` builds the `pg` pool with no listener of its `error` event.
- Where the backend composes its database and its log (the server pack names the files).
- `.claude/launch.json` and the `scripts` of the root `package.json`.

## Work

Change no manifest. The defect, as step 05.7 saw it: with the backend running, the PostgreSQL went away, and the process ended with `Unhandled 'error' event`, `terminating connection due to administrator command`, `Emitted 'error' event on BoundPool instance`. An idle client the server ends emits `error` on the pool, and an `error` event with no listener ends a Node process.

1. The pool has a listener of `error` from the moment it is built. The backend logs what it receives through its own log, as one entry, with URL credentials cut as every other logged text is. Census every caller of `openDatabase` (the server, the wipe command, the tests' helpers) before you choose how the listener is passed: none of them may be left with a pool that can end its process.
2. Tests, with these titles:
   - `a connection the server ends does not end the process` (open a database, run a query so that the pool holds an idle client, end that backend with `pg_terminate_backend` from a second connection, see the listener receive the error, then see a further query through the first database succeed)
   - `the backend logs a connection the server ends and goes on` (the composed backend: after the same termination its log holds the entry and `/readyz` still answers)
   Plant a fault for each (the listener removed) and see it fail, restoring from a copy. A test that ends the test process when it fails is the expected way for the first to fail: say in your report what you saw.
3. `.claude/launch.json` calls `yarn dev`, which the root `package.json` names `dev:ui`: correct it, and check every other root script the file calls against the root `scripts`.
4. Every test that exists still passes.

## Done when

`agent-work/stages/05-integrate/checks/05.8.sh` proves the two tests exist and pass with the repository checks, and that the launch file calls no `yarn dev` followed by a space. It cannot prove the backend survives a real failover: the final review reads the listener.
