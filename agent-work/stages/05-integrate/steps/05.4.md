## Goal

A verdict on every outcome of `../../../architecture.md`, from the merged code and from what you
ran, and every other defect of the whole branch marked `blocking` or `advisory`.

## Read first

- `../../../architecture.md`: `## Outcomes` first, then the design.
- `../../../decisions.md`
- The change itself: `git diff --stat 942e473...HEAD`, then the files that carry each outcome.

## Work

1. For each outcome, find the code that delivers it and run something that shows it: a test, a
   command, a request to the running thing. Reading alone never gives `met`.
2. Look for what a review of one stage cannot see: two stages that each pass and disagree where
   they meet, a decision the code does other than, a check that passes without the work.
3. You are given the code and the design. The builders' reports and the earlier reviews stay
   closed to you.
4. In `FINDINGS`, one line per outcome first: `O1: met <the evidence>` or
   `O1: not met <what is missing>`. Then one line per finding, starting `blocking:` (the code
   does other than the design says, loses data, leaks a secret, or an outcome is not met) or
   `advisory:` (anything else). Continue a line by indenting. `none` when there is no finding.

## Done when

`checks/05.4.sh` proves the report gives every outcome a verdict and every finding a mark. It
cannot prove a verdict is right: the orchestrator reads the evidence beside each.
