## Goal

`packages/backend/Dockerfile` builds the backend's image from the repository root, and a developer starts a PostgreSQL and the backend with root scripts (D09, D14, D25, D60).

## Read first

- `agent-work/decisions.md`: D25 and D60.
- `packages/ui/Dockerfile:6-24`: the pinned Node image and the checked Yarn release to match.
- `.dockerignore`, whole: what both images' context leaves out.
- `packages/backend/src/main.ts`: the entry the image runs, and its `wipe-network` argument. It logs one JSON object a line with `time`, `level`, `message` and, for a cycle, `network`: the exit check reads those lines from the container.

## Work

1. `packages/backend/Dockerfile`, built from the repository root with `docker build -f packages/backend/Dockerfile .`: the Node image and the Yarn release `packages/ui/Dockerfile` pins, `yarn workspaces focus @sig-net/explorer-backend --production`, the sources of `packages/lib`, `packages/api` and `packages/backend`, `USER node`, `EXPOSE 8080`, `CMD ["node", "packages/backend/src/main.ts"]`. Node runs the TypeScript sources: there is no build step. Yarn needs every workspace's `package.json` to resolve the lockfile, and none of the UI's sources.
2. Change `.dockerignore` only if the build needs it. `agent-work` and `**/.env*` stay out of the context, and the UI's image must still build: `docker build -f packages/ui/Dockerfile -t explorer-05-7-ui . && docker rmi explorer-05-7-ui`.
3. `packages/backend/compose.yaml`: one service, PostgreSQL 17, published on `127.0.0.1:${EXPLORER_POSTGRES_PORT:-5432}`, with a password a developer's `EXPLORER_DATABASE_URL` can name and a named volume.
4. `packages/backend/package.json` gains `"dev": "node --env-file-if-exists=.env.local src/main.ts"`. The root `package.json` gains `db:up` (`docker compose -f packages/backend/compose.yaml up -d --wait`), `db:down` (`docker compose -f packages/backend/compose.yaml down`) and `dev:backend` (`yarn workspace @sig-net/explorer-backend dev`), and its `dev` is renamed `dev:ui` (D60). `grep -rn 'yarn dev' --exclude-dir=node_modules --exclude-dir=agent-work --exclude-dir=dist .` and list in your report every hit outside your scope: the README's are step 05.3's.
5. Try it once by hand, under a Compose project name of your own and a free port: `EXPLORER_POSTGRES_PORT=<port> docker compose -p explorer-05-7 -f packages/backend/compose.yaml up -d --wait`, start the backend against it with a `packages/backend/.env.local` (which git ignores) that takes the Blockfrost project id from the dev secrets inside the command, see `/readyz` answer 200, then `docker compose -p explorer-05-7 -f packages/backend/compose.yaml down -v` and delete the env file. Report the image's size.
6. `yarn format`, then the exit check, which builds the image and indexes preprod for a few seconds.

## Done when

`agent-work/stages/05-integrate/checks/05.7.sh` proves the scripts and the compose file exist, the repository's checks pass, the image builds and runs as a user other than root, a container of it beside a PostgreSQL answers `/healthz`, `/readyz` and `/v1/networks` while it stores a first range of preprod, logs JSON lines with no token, exits 0 on SIGTERM, wipes `preprod` with exit 0 and refuses an unknown network with exit 1. It cannot prove the image holds nothing it does not need: the final review lists its files.
