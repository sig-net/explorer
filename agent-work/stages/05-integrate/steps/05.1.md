## Goal

`node packages/backend/src/main.ts` is the backend: it migrates, indexes every configured network and serves the API. `node packages/backend/src/main.ts wipe-network <network>` wipes one (D14, D56 to D59).

## Read first

- `agent-work/decisions.md`: D12, D14, D51, D56, D57, D58 and D59.
- The server pack names every part you compose with its file and line. Read those signatures, not their bodies.

## Work

1. `EXPLORER_HOST` in `parseBackendEnv` (D59): optional, a string without white space, default `0.0.0.0`, as `BackendConfig.host`. Tests beside the existing ones, and the whole-configuration assertion gains `host`.
2. `TestDatabase` of `src/db/testing.ts` gains `url`, the URL of the database it made, so that a test can hand it to `startBackend` and to a child process.
3. `src/backend.ts` exports `startBackend(config, dependencies)`. The dependencies are what a test replaces: `createSource(network: BackendNetworkConfig): MidnightSource`, `inspect`, `log(entry)`, and optionally `sleep` (the loop's) and `migrate` (default `migrateNetworkSchema`). It opens the pool, builds the service and the app, and serves it with `serve` of `@hono/node-server` on `config.host` and `config.port` (0 lets the system choose, for tests). A port that is taken rejects it. It resolves as soon as it listens, with `{ port, started, stop }`:
   - `started` is a promise: it runs `migrate` for each network, then `ready()` turns true and one `startIngestLoop` starts per network (`pollIntervalMs` is `pollIntervalSeconds * 1000`). A migration that fails is logged, everything is closed, and `started` rejects (D56).
   - `stop()` may be called at any moment, and follows D57: `ready()` turns false, the server stops accepting and closes its open connections, every loop's signal aborts, the loops are awaited for at most 8 seconds, the pool is destroyed.
   - One network's loop failing or stopping never ends another's.
4. The same file exports `wipeNetwork(config, networkArgument)` (D58): for a network of `config.networks` it opens a pool, runs `wipeNetworkSchema` then `migrateNetworkSchema`, closes the pool and returns the schema's name. Any other argument throws an error that lists the configured networks, before anything is opened.
5. Logs (D59). `log` takes `{ level: 'info' | 'error', message, network?, ...fields }`. `backend.ts` passes every text through `textWithoutUrlCredentials` before it calls `log`. It logs `listening` with `host` and `port`, each migration, a cycle that answers `stored` (`info`, with its blocks and event count), `failed` or `stopped` (`error`, with the reason) or `superseded` each time, `caught-up` only when the network's outcome before it was of another kind, the errors `createHttpApp` reports, and the shutdown.
6. `src/main.ts`, the entry, holds no logic beyond this: its `log` stamps `time` (ISO 8601) and writes one JSON line to stdout. `parseBackendEnv(process.env)` (a failure prints its message and exits 1). With no argument: `startBackend` with `createIndexerSource` and `inspectTransactionForStorage`, SIGTERM and SIGINT call `stop()` and exit 0, and a rejection of `startBackend` or of `started` exits 1. With `wipe-network <network>`: `wipeNetwork`, print the schema dropped, exit 0, or print the error and exit 1. Anything else prints the usage and exits 1.
7. `src/backend.test.ts` runs the composition in-process with in-memory sources on a database of `createTestDatabase`, and `src/main.test.ts` starts `node src/main.ts` as a child with `EXPLORER_HOST=127.0.0.1` and a port the test took free from the system. Each test that waits on a child or on `stop()` sets its own timeout of 60 s, and none asserts a wall time under ten seconds: the machine is shared and loaded. Titles, the first seven in `backend.test.ts`:
   - `indexes the in-memory chain and serves it through the api client`
   - `serves what was stored before a restart and continues from the cursor`
   - `one network that stops leaves the other indexing` (one of two networks restarts over a source with another genesis hash and answers `stopped`, the other's cursor moves)
   - `readyz turns 200 after the migrations` (a `migrate` the test holds back: 503 while it waits, 200 after, 503 again after `stop()`)
   - `wipe-network drops one schema and the loop indexes it again` (the other network's rows stay)
   - `wipe-network of an unknown network drops nothing`
   - `no log line carries a URL's query string` (a `migrate` that rejects with an error holding `https://indexer.test/api?project_id=secret`: the entry holds the URL without `project_id`)
   - `SIGTERM ends the process cleanly` (the child serves `undeployed` from an indexer URL nothing listens on, logs `listening`, answers `/readyz` with 200, and exits 0 on the signal with every stdout line a JSON object)
   - `a database that does not answer at start exits 1`
8. No comment you write cites a decision number or `agent-work`. `src/index.ts` stays as it is. `yarn format`, then the exit check.
