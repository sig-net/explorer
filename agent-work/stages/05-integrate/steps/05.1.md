## Goal

`node packages/backend/src/main.ts` is the backend: it migrates, indexes every configured network and serves the API. `wipe-network <network>` wipes one. `packages/backend/Dockerfile` builds its image (D09, D14).

## Read first

- `packages/backend/src/config/`, `http/`, `ingest/`, `service/`, `source/`, `db/`: the exported functions you compose. Read their signatures, not their bodies.
- `packages/ui/Dockerfile`: the pinned Node image and the Yarn install to match.

## Work

1. `src/main.ts`, with no logic of its own beyond composition:
   - `parseBackendEnv(process.env)`. A failure prints the message and exits 1.
   - With no argument: connect, `migrateNetworkSchema` for each network, start one `startIngestLoop` per network with a source from `createIndexerSource` and the inspection, build the service with each network's display configuration, serve `createHttpApp` on the port. `ready()` is true once every network's migration has run and the database answers.
   - One network's loop failing or stopping never ends the process or another network's loop.
   - SIGTERM and SIGINT: stop accepting, abort the loops, let a running cycle's transaction finish or roll back, close the pool, exit 0, within 10 seconds.
   - `wipe-network <network>`: `wipeNetworkSchema` for a configured network, print what was dropped, exit 0. An unknown network exits 1 and drops nothing.
2. Logs are one JSON object a line on stdout, with no URL query string in any field.
3. `packages/backend/Dockerfile`, built from the repository root: the Node image the UI's Dockerfile pins, `yarn workspaces focus @sig-net/explorer-backend --production`, the sources of `lib`, `api` and `backend`, a non-root user, `EXPOSE 8080`, `CMD ["node", "packages/backend/src/main.ts"]`. Update `.dockerignore` so the context holds what both images need.
4. `packages/backend/compose.yaml`: a PostgreSQL 17 for local work on `127.0.0.1`, and root scripts `dev:backend` and `db:up`.
5. `src/main.test.ts` starts the composition in-process with the in-memory source and a real PostgreSQL. Titles:
   - `indexes the in-memory chain and serves it through the api client`
   - `serves what was stored before a restart and continues from the cursor`
   - `one network that stops leaves the other indexing`
   - `readyz turns 200 after the migrations`
   - `wipe-network drops one schema and the loop indexes it again`
   - `wipe-network of an unknown network drops nothing`
   - `SIGTERM ends the process cleanly`

## Done when

`checks/05.1.sh` proves the seven tests pass, the image builds, and a container of it with a PostgreSQL beside it answers `/healthz`, `/readyz` and `/v1/networks`, and exits 0 on SIGTERM.
