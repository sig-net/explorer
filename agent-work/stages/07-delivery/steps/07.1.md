## Goal

Two images build from the workspace (D26): the UI's nginx image, as today, from the root
`Dockerfile`, and the backend's from `packages/backend/Dockerfile`, which starts as `ingest`,
`serve` or both from its environment and carries no configuration.

## Read first

- `../../../architecture.md`, sections 9 and 10. `../../../decisions.md`: D18, D26 and the
  verdict of G10 (does Node run the source with no build).
- `Dockerfile`, `docker/nginx.conf`, `docker/30-explorer-env.sh`, `.dockerignore`.
- `packages/backend/package.json` (the scripts `start` and `migrate`) and `src/main.ts`.

## Work

1. `packages/backend/Dockerfile`, built with the repository root as its context. A build stage
   on the Node image the root `Dockerfile` pins installs the workspace's production
   dependencies for `@explorer/backend` from the frozen lockfile, with the same checked Yarn
   release. The runtime stage is the same Node image, slim: the three packages' sources
   (`lib`, `api`, `backend`), the migration folder and `node_modules`, run as a user that is
   not root. No UI, no dev dependency, no test, no drill in it. `ENTRYPOINT` runs
   `node packages/backend/src/main.ts` (through `tsx` only if G10 said so) and `CMD` is
   `start`, so that `docker run <image> migrate` runs a command. `EXPOSE` the HTTP port's
   default. Inside a container the listener must bind `0.0.0.0`: set the variable step 05.1
   defined for it.
2. The root `Dockerfile`: check that it still builds the UI from the workspace and that its
   opening comment says which variables the image reads at start (the ones
   `docker/30-explorer-env.sh` writes after stage 05). Change what is no longer true.
3. `.dockerignore`: both builds share it. Leave out what neither needs. Do not remove the
   `agent-work` line: it goes with the folder.
4. Build both: `docker build -t explorer-replan-ui:07 .` and
   `docker build -f packages/backend/Dockerfile -t explorer-replan-backend:07 .`. Report each
   image's size.
5. Run the backend image against the local Postgres on a scratch database: `migrate`, then
   `start` with the role `serve`, and get `/healthz` and `/network/listNetworks` from the
   host. On this machine a container reaches the host's Postgres through
   `--add-host=host.docker.internal:host-gateway`. Stop and remove the container.
6. Run the UI image with `VITE_EXPLORER_BACKEND_URL` set and read `/env.js` from it: it must
   hold that variable.
7. Remove the two test images and the containers you made. Commit.

## Done when

`checks/07.1.sh` proves both images build, the backend image runs `migrate` and serves
`/healthz` as a user that is not root and holds no UI and no test file, the UI image's `env.js`
carries the backend URL, and nothing of the check is left running.
