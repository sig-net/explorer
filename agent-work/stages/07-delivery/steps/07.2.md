## Goal

A person who was not here can run, operate and change the system from the repository's own
documents: the `README.md` describes the explorer as it is now, `docs/architecture.md` and
`docs/decisions.md` hold the design as built and the reasons for it (D33), and `AGENTS.md`
holds the rules that keep the new boundaries. Every command quoted was run as quoted.

## Read first

- `../../../architecture.md` and `../../../decisions.md`, whole: the source of the two `docs/`
  files. They are agents' files and are removed when the pull request opens, so nothing you
  write may point a reader at them or at any `agent-work/` path.
- `README.md`, whole, and `AGENTS.md`, whole.
- `packages/backend/.env.example`, `packages/backend/package.json` and the root `package.json`
  (every script), `compose.yaml`, `packages/backend/src/commands/`.

## Work

1. `docs/architecture.md`: the design AS BUILT, in the present tense, for people: the shape,
   the packages and who may import whom, the data model, how ingestion loses no event and what
   that guarantee does not cover, the chain source seam, the API, what the UI does in the
   browser, operations. Where stages 01 to 06 changed the settled design (every `orchestrator`
   row of the decisions), write what is true now. No stage numbers, no gate ids, no step ids.
2. `docs/decisions.md`: each decision that shapes the code, with its reason, as a list a
   person reads. Leave out the ones about how the work was planned (the probes, the scratch
   branch, the stage numbering).
3. `README.md`: rewrite what the change made untrue, keep what is still true. It must cover:
   what the explorer is now (a UI and a backend). Requirements (Node, Yarn, Docker for
   Postgres). Running it locally, step by step: Postgres up, the backend's `.env` from the
   example, `migrate`, `start`, the UI's dev server with the backend URL. Every variable of
   the backend and of the UI, in two tables, saying which are secrets. The commands and when
   to use each: a schema change (wipe), a redeployed contract or a network reset
   (`reset-network`), a halted network (what it means, how to find the reason, how to recover),
   the audit. The checks, the end to end run and the drills. The two images. GitHub Pages.
   The sections about the theme, Tailwind, routing and the SDK link stay unless untrue.
4. Run EVERY command you quote, exactly as quoted, from a fresh clone of your branch in a
   temporary folder, before you write the sentence that quotes it. List them in your report.
5. `AGENTS.md`: the rules file of this repository. Add, in its own voice and sections: the
   dependency direction of the four packages. `lib` and `api` run in both runtimes. TypeScript
   that Node can strip in `lib`, `api` and `backend`. No reply and no log carries a URL of an
   indexer or an EVM node. The backend serves facts and no verdict. One migration, regenerated,
   and no start-up erasure. A new table with `network_id` joins the reset. The fakes never
   reach the production bundle. Update every path the earlier stages moved. Change nothing
   else in it.
6. No package gets a README of its own unless it says something the root one does not: prefer
   none.
7. `yarn format`, `yarn lint`, `yarn format:check`. Search what you wrote for the marker words
   of history (`previously`, `no longer`, `used to`, `instead of`, `rather than`) and rewrite
   each hit in the present tense. Commit.

## Done when

`checks/07.2.sh` proves the three documents exist, name every variable and every command, point
at no agent file, name no variable or file that stage 05 removed, and pass the format check. It
cannot prove a quoted command works or that the prose is right: the orchestrator runs the local
run section once, top to bottom, on a fresh clone.
