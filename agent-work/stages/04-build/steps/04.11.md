## Goal

No inspection result can fail the storing transaction: what PostgreSQL's `jsonb` or `text` refuses is stored as a failed inspection and the ingest goes on (D23, D52).

## Read first

- `agent-work/decisions.md`, D23, D38 and D52.
- `packages/backend/src/ingest/ingest-cycle.ts`, where an inspection is turned into the stored value and where a thrown reason is recorded.
- `packages/backend/src/inspection/sign-bidirectional-transaction-inspection.ts:90-100`: an entry point name comes from the transaction's bytes and reaches `callChains`.

## Work

Change no manifest. The defect, as the review reproduced it: the fixture transaction with one byte of `sendDeposit` set to 00 deserialises, the inspection returns the entry point `"send\u0000eposit"`, and the cycle answers `failed: unsupported Unicode escape sequence` on every retry with the cursor unmoved. The same holds for a thrown reason that holds `\u0000`.

1. In the ingest, at the one place a stored inspection is made for a transaction: a value whose strings hold a NUL character (U+0000), anywhere in it, is replaced by `{ failed: <reason> }` for the whole transaction, with a reason that says the inspection holds a character the store refuses. Check the value itself, never by catching the database's error, which would abort the transaction.
2. Every text the cycle stores from outside (a thrown reason, a returned `failed` reason, `last_error`) loses its NUL characters before it is stored, in the one function that already bounds and cuts such texts.
3. Tests, with these titles:
   - `an inspection holding a NUL character is stored as a failed inspection` (the cycle answers `stored`, the cursor moves, the transaction's inspection is `{ failed }`, the events are stored)
   - `a thrown reason holding a NUL character is stored` (the same, for an inspection that throws such a reason)
   Plant a fault for each and see it fail, restoring from a copy.
4. Every test that exists still passes.

## Done when

`agent-work/stages/04-build/checks/04.11.sh` proves the two tests exist and pass with the ingest's other tests and the repository checks. It cannot prove no other value the store refuses exists: review 04.13 attacks the fix.
