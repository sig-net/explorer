## Goal

An expanded row gets its events from `getSignRequest`, decodes them in the browser, and verifies
them exactly as today. The raw Midnight transaction comes from the Midnight transaction service
and the trace fallback from the Ethereum transaction output service. The browser no longer asks
an indexer or a keyed EVM node for either. Every check a user sees gives the same verdict.

## Read first

- `../../../architecture.md`, sections 1 and 8. `../../../decisions.md`: D02, D11 and the
  outcome of G16 (what the trace service returns).
- `packages/api/src/sign-request/signet-event.ts` and the three other resources.
- `packages/lib/src/signet-events.ts`: the event type, generic over its source.
- Every file of your scope, whole. They are the subject.

## Work

1. `lib/midnight/stored-signet-event.ts`: from a `SignetEvent` of the API to the UI's decoded
   event: payload hex to the 256 bytes, `decodeSignetContractEvent` from `@explorer/lib` with
   the stored roles, and a source that carries the chain position, hashes, height and block
   time. Give it `eventKey(event)`, the string `<blockHeight>:<blockPosition>`. The stored
   `kind` and the browser's decode must agree: when they do not, show the event with the
   browser's result and both facts, never hide it.
2. Replace the indexer's event id as a key by `eventKey` everywhere the `ui-census` pack lists
   it: the tabs, the verification maps, the ordering inside a lifecycle. `source.id` must not
   be read anywhere in your scope afterwards.
3. `sign-bidirectional-lifecycle-details.tsx`: takes the network and the request id, loads
   `getSignRequest` with `usePolledQuery`, builds the lifecycle from the returned events, and
   renders the three sections as today. Its loading and error states use the existing splash
   and alert components. Export the render function the list's `renderDetails` prop takes.
4. The raw transaction: the loader asks `getMidnightTransaction` in place of the indexer, keyed
   by network and hash. Keep the dynamic `import()` of the inspection module exactly where it
   is: it is what keeps the ledger WebAssembly off the first load.
5. The trace: `use-lifecycle-verification.ts` asks `getEthereumTransactionOutput` in place of
   the node. If G16 chose the frame as served, the browser applies
   `evmTraceOutputFromCallFrame` as it does today. The MPC output cache and the transaction
   STATUS display keep their direct calls from the browser.
6. Where these files read the root key and the signer address from the editable configuration,
   read them from the selected network's deployment in `listNetworks` instead. The EVM RPC
   URLs for the status display and the MPC cache URL stay with the build's configuration.
7. Tests with the fakes: a request whose signature and attestation verify, one whose second
   signature response is the valid one, an attestation whose output comes from the trace
   service, a refused transaction and a refused trace shown as today's errors, a request that
   gains its response at the next poll.
8. `yarn lint`, `yarn build`, `yarn check`. Count the `.wasm` files and confirm the ledger one
   is referenced by the lazy chunk alone. Commit.

## Done when

`checks/04.9.sh` proves the files exist, nothing in scope reads the indexer's event id, queries
an indexer or calls `debug_traceTransaction`, the WebAssembly rule holds, and all checks pass.
It cannot prove the verdicts equal today's on real requests: stage 05 compares them on preprod.
