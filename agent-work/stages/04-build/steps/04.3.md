## Goal

`createPostgresExplorerService(db, networks)` implements the api package's `ExplorerService` over the tables and the `lifecycle` view, answers exactly as the in-memory service does, and stays fast at 200,000 requests.

## Read first

- `agent-work/decisions.md`, D36, D37, D41 to D45.
- `packages/api/src/service.ts`, `packages/api/src/testing.ts:33-100` (the in-memory service, whose rules you match), and in `packages/api/src/wire.ts` `resolveLifecyclesQuery`, `lifecycleWireSchema`, `lifecycleFromWire`, `urlWithoutCredentials`.
- `packages/backend/src/db/schema.ts`, `testing.ts` (`createTestDatabase`, `seedNetworkEvents`, `storedInspectionsOfSeed`) and `migrations/0001_network_tables.sql`.

## Work

Change no manifest and no file of `src/db`: a need there is a finding.

1. `networks` is a list of `{ network, config: ExplorerNetworkConfig }`, the served networks, whose schemas the caller has migrated. `networks()` gives each with `config.sourceUrl` cut by `urlWithoutCredentials`, as the in-memory service does, and `sync` from its `ingest_state` row: `processedBlock` is `cursor_height`, `error` is `last_error`. With no row the state is `starting` and every other field null. A network outside the list is the `unknown_network` error, in every method.
2. `lifecycles`: pass the query through `resolveLifecyclesQuery`. Choose the page's request ids on `requests` alone (`first_event_id DESC`, keyset on `before`, `limit + 1` rows to learn `nextBefore`), then read those rows from the view and turn each into the domain type with `lifecycleWireSchema` and `lifecycleFromWire`.
   - A non-empty fragment filters in the UNION form of D42, with `\`, `%` and `_` escaped in the pattern.
   - `excludeCallers` is a `NOT EXISTS` on `request_callers`, so a request with no caller is kept.
   - The counts follow D43: all read from `requests` and `events`, never through the view, in one read only `REPEATABLE READ` transaction with the page. `matchingEvents` is the sum of the three count columns of the matching rows (D37).
3. `lifecycle` reads one view row by `request_id`. `callers` is the distinct callers of `request_callers`, ascending in the `"C"` collation.
4. Every input is a bound parameter. A raw fragment qualifies its tables with `sql.id` (contract pack). No `sql.raw` and no `sql.lit`.
5. Tests against a real PostgreSQL, with these titles. The large ones seed with `generate_series` and `md5` in SQL (request ids and callers must look random, contract pack), run `VACUUM (ANALYZE)`, and time the second call:
   - `answers as the in-memory service for the shared seed` (seed `explorerSeed`'s preprod with `seedNetworkEvents` and write its `sync` into `ingest_state`. Compare `networks`, `lifecycle`, `callers`, and `lifecycles` over searches (empty, 2 characters, `%`, `_`, `\`, `0x` and upper case, a full id, a caller fragment), exclusions and page sizes)
   - `pages through 500 requests without repeating or skipping one`
   - `search matches a fragment in any case with or without 0x`
   - `search treats percent, underscore and backslash as text`
   - `excluding callers keeps requests that name no caller`
   - `counts the matching requests and events and the totals`
   - `reports starting, syncing, synced and stopped`
   - `an unknown network is the typed error`
   - `the newest page of 200,000 requests answers within 500 ms`
   - `a search of 200,000 requests by a fragment of a request id answers within 500 ms`
   - `a search of 200,000 requests by a fragment of a caller answers within 500 ms`
   - `excluding a caller of 200,000 requests answers within 500 ms`
   - `the callers of 200,000 requests answer within 500 ms`
   - `a selective search reads neither requests nor request_callers in full` (`EXPLAIN` of your own page and count statements for a 12 character fragment: no `Seq Scan`)
6. In your report, under FINDINGS, give the time each of the five timed tests measured.
