## Goal

`Ingester` runs the loop of section 5 for one network: whole ranges, ascending, the checkpoint
advanced in the same transaction as the rows, one writer, a halt in place of a skip. Every rule
of that section has a test that drives the loop with the fake chain source against a real
Postgres.

## Work

1. `ingester/ingester.ts`: a class built from a network id, its deployment (addresses, root
   key, start block), a chain source, the repositories, the unit of work, a logger and its
   settings (`safetyMargin`, `rangeSize`, `rereadBlocks`, `pollIntervalMs`), whose defaults are
   constants defined here from stage 01's numbers, each with the gate it came from.
2. `runOnce()` is one turn of the loop and returns what it did. `run(signal)` repeats it with
   the poll interval until the signal aborts. Tests drive `runOnce`. No timer in a test.
3. Start of a network: take the advisory lock for the network on a dedicated connection and
   hold it for the life of `run`. Compare the configured deployment with the stored one: equal,
   go on. None stored: check `contractExistsAt(start_block - 1)` is false for both contracts,
   store the deployment and a checkpoint at `start_block - 1` with that block's hash.
   Different: refuse, with a message that names the reset command and no value.
4. One turn, exactly as written in section 5: head, target, the hash check under the
   checkpoint, ranges, and for each range ONE transaction holding the events, the sign request
   rows and the checkpoint. Then the trailing re-read: read the last `rereadBlocks` again and
   compare with what is stored, event for event.
5. Halting: a changed hash, a `ChainDataConflict`, a re-read that differs, or a range that has
   failed `maxRangeAttempts` times in a row sets `state = halted` with a reason in the
   checkpoint, in its own transaction, and stops the network's loop. A halted network stays
   halted across restarts until it is reset. A failure below the limit leaves the checkpoint
   where it was and is retried next turn.
6. `head_block` and `update_time` are written every turn, also when there is nothing to read.
7. Tests, one per rule, each named for the rule: a fresh start begins at the start block. A
   contract that exists before the start block refuses. Ranges are whole and ascending and the
   checkpoint never passes `head - safetyMargin`. A crash between read and commit (the fake
   throws inside the transaction) replays to the same rows. A replay with a different row
   halts. A changed hash halts. A late event is caught by the re-read and halts. A range that
   keeps failing halts and is never stepped over. A second ingester cannot take the lock. A
   changed deployment refuses. After every scenario the aggregate equals a rebuild from events.
8. `yarn lint`, `yarn build`, `yarn check`. Commit.
