## Goal

`runIngestCycle` reads one range from a `MidnightSource` and stores it with the cursor in one transaction, and `startIngestLoop` repeats it for one network, so that no failure can leave the cursor past data that is not stored (O4, D06).

- `agent-work/architecture.md`, "Ingest: a cursor that moves only with complete data".
- `packages/backend/src/source/port.ts`, `in-memory.ts`, `packages/backend/src/db/schema.ts`, `testing.ts` and the migrations.

## Work

1. `runIngestCycle(deps, settings)`, where `settings` is `network`, the two contract addresses, `startBlock`, `maxRange` (default 2,000 blocks) and `tipMargin`:
   1. No `ingest_state` row: write one with the source's genesis hash, the addresses, the start block and the cursor at `startBlock - 1` with the hash and time `blockAt(startBlock - 1)` gives, and `state` `syncing`.
   2. Identity: the stored genesis hash, addresses and start block equal the source's and the settings', and `blockAt(cursor_height)` has the stored hash. Otherwise set `state` to `stopped` with the reason and return, writing nothing else (D12).
   3. `target = min(tip - tipMargin, cursor + maxRange)`. Nothing to read: record the tip, success and `state` `synced`, return. Otherwise read `blockAt(target)` now, for the new cursor's hash and time. A null answer fails the cycle.
   4. Read the events in `(cursor, target]`, decode each with lib, and for each sign bidirectional event fetch and inspect its transaction once, at most 8 fetches at a time (a full preprod history is over 5,000 transactions).
   5. One transaction: insert transactions and events, upsert each request's row from ALL its stored events (recompute the row, never add to it), update `ingest_state` with the new cursor `WHERE cursor_height = <the value read in step 2>`. The same update sets `tip_height`, `last_success_at`, clears `last_error`, and sets `state` to `synced` when `target` is the tip less the margin and `syncing` otherwise. If that update changes no row, roll back.
2. A source failure or a database failure rolls back and is recorded in `last_error` (with no query string), in a separate statement. An inspection that throws is stored as failed (D23). A raw transaction that cannot be fetched fails the cycle.
3. `startIngestLoop(deps, settings, { pollIntervalMs, signal })`: cycles until the cursor is at the target, then waits the interval. After a failure it waits with exponential backoff from the interval up to 5 minutes, and resets on success. A `stopped` network is checked again every interval, so that it resumes after a wipe with no restart.
4. Tests against a real PostgreSQL and the in-memory source, with these titles:
   - `the first cycle records the identity and starts at the start block`
   - `stores a range and moves the cursor together`
   - `a failing read leaves the cursor and the tables unchanged`
   - `a failure inside the transaction stores nothing`
   - `reading a range again stores nothing twice`
   - `of two cycles from one cursor only one commits`
   - `a changed genesis hash stops the network and writes nothing`
   - `a replaced cursor block stops the network`
   - `changed contract addresses stop the network`
   - `never reads past the tip less the margin, nor more than the range`
   - `a response stored before its request completes the same row`
   - `stores an event that does not decode without a request row`
   - `inspects a transaction once and stores a failed inspection`
   - `a transaction that cannot be fetched fails the cycle`
   - `backs off after failures and resets on success`
   - `a stopped network resumes after its schema is wiped`
   - `the recorded error carries no query string`
