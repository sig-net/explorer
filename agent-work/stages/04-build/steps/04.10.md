## Goal

`startIngestLoop` repeats `runIngestCycle` for one network until it is told to stop, backs off while the source or the database fails, and picks a stopped network up again after an operator's wipe (D12, D14).

## Read first

- `agent-work/decisions.md`, D12, D14, D29, D45 and D50.
- `packages/backend/src/ingest/`: `runIngestCycle`, its outcome type and its tests, which show how a test builds a chain and a database.
- `packages/backend/src/db/migrate.ts` (`migrateNetworkSchema`, `wipeNetworkSchema`).

## Work

Change no manifest, no file outside `src/ingest`, and nothing of what `runIngestCycle` does: a defect you find there is a finding, with a failing test if you can write one.

1. `startIngestLoop(deps, settings, { pollIntervalMs, signal, onOutcome, sleep }): Promise<void>`, an exported function declaration, with the `deps` and `settings` of `runIngestCycle`. It resolves when `signal` aborts, after the cycle in flight has returned, and it never rejects.
2. After `stored` it cycles again at once. After `caught-up`, `stopped` and `superseded` it waits `pollIntervalMs`. After the n-th `failed` in a row it waits `pollIntervalMs * 2^n`, at most 300,000 ms, and any other outcome resets n. A cycle that rejects (the database is down, so that not even the error could be recorded) counts as `failed`, with its message cut by `textWithoutUrlCredentials`.
3. `onOutcome(outcome)` is called after every cycle: it is how stage 5 logs. A throw of it is ignored.
4. `sleep(ms, signal)` is a dependency, with a default that waits on a timer and returns early when the signal aborts. Tests pass their own and need no clock.
5. A `stopped` network is cycled again every interval, so that after `wipeNetworkSchema` and `migrateNetworkSchema` the next cycle indexes it from the start block with no restart. Between the wipe and the migration a cycle fails on the missing tables, which is a `failed` like any other.
6. Tests against a real PostgreSQL and the in-memory source, with these titles:
   - `cycles at once while there is more to read and waits once caught up`
   - `backs off after failures and resets on success`
   - `a cycle that rejects backs off and the loop goes on`
   - `stops when the signal aborts`
   - `a stopped network resumes after its schema is wiped and migrated`
   - `reports every outcome`
