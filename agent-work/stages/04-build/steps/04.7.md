## Goal

The UI can reach the four services: a context provides them (HTTP clients in the app, anything
a test injects), a hook polls a query, and the build knows `VITE_EXPLORER_BACKEND_URL`. The
table's file is split so that the list and the expanded row can be changed by two agents at
once. Nothing a user sees changes yet.

## Work

1. Add `@explorer/api` to `packages/ui` as `workspace:*`. `yarn install`, commit the lockfile.
   You are the only step of this stage that may.
2. `VITE_EXPLORER_BACKEND_URL`: declare it in `vite-env.d.ts`, and widen the reader in
   `explorer-env.ts` to carry it beside the `VITE_MIDNIGHT_*` keys (its key type is derived
   from a prefix today: the name of that type and of the file's doc comment must still be true
   after you widen it). Add `lib/explorer-backend/backend-url.ts`: `parseExplorerBackendUrl`
   returns the http or https URL with no trailing slash, or null when the variable is unset or
   empty, and throws an error naming the variable for anything else.
3. `components/contexts/ExplorerBackendContext.tsx`, one file: the value type (the four
   service interfaces, or the fact that no backend is configured), `ExplorerBackendProvider`,
   which builds the HTTP clients from the parsed URL unless a `services` prop is given, and
   `useExplorerBackend`. Mount it in `__root.tsx` outside `MidnightProvider`. Import
   `@explorer/api/http` only: `@explorer/api/fakes` must not be reachable from any file that
   is not a test (D30).
4. `components/use-polled-query.ts`: `usePolledQuery(key, load, intervalMs)` returns
   `{ status: 'loading' | 'loaded' | 'error', data, error, refresh }`. It loads on mount and
   whenever `key` changes, again every interval while the document is visible, keeps the last
   data while a reload runs, drops a result that arrives for an old key, and stops on unmount.
   The default interval is one named constant.
5. Tests of the hook with a hand-written `load`: the first load, a key change that discards a
   late answer, an error that keeps the last data, `refresh`, and the interval, driven by
   vitest's fake timers.
6. Move `LifecycleDetails` and what only it uses out of the table's file into
   `sign-bidirectional-lifecycle-details.tsx`, unchanged, and import it back. The table's test
   passes untouched.
7. `yarn lint`, `yarn build`, `yarn check`. Count the `.wasm` files of the build. Commit.

## Done when

`checks/04.7.sh` proves the context, the hook with its test and the details file exist, the

the two WebAssembly files are the only ones, and all checks pass with no test lost.
