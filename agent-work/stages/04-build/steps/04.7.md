## Goal

The UI offers the networks the backend serves, shows each network's server configuration read only (D11), shows how far the backend has indexed, and holds no setting of a Midnight indexer or node.

## Read first

- `packages/api/src/`: what `networks()` returns.
- `packages/ui/src/lib/midnight/network.ts`, `explorer-env.ts`, `vite-env.d.ts`, `packages/ui/src/components/contexts/MidnightContext.tsx`, `packages/ui/src/components/midnight/midnight-configuration.tsx`, `network-switcher.tsx`, `packages/ui/docker/30-explorer-env.sh`, with their tests.

## Work

1. `MidnightNetworkConfig` keeps only what the browser itself uses and the user may edit (D10): `mpcRootPublicKey`, the two EVM RPC URLs, `mpcOutputCacheUrl`. Remove `indexerUrl`, `indexerWsUrl`, `nodeUrl`, `signerContractAddress`, `responderContractAddress`, `signetEventsFromBlock`, their parsers, the Blockfrost URLs and `SIGNET_EVENTS_EARLIEST_BLOCKS`.
2. Remove from `vite-env.d.ts` and `parseRuntimeExplorerEnv` every variable that set a removed field (the Blockfrost project id, the signer, responder and from-block variables of every network). The UI image's entrypoint needs no change if it still writes every `VITE_MIDNIGHT_*` and `VITE_EXPLORER_*` variable: make it write both prefixes.
3. `MidnightContext.tsx` reads `networks()` once and on Refresh, and exposes for the selected network its server configuration and sync state. The MPC output cache location takes `signerContractAddress` from the server configuration.
4. The network switcher marks a network the backend does not serve as unavailable. Selecting it shows "This backend does not index <network>".
5. The configuration popover: a read only section "Indexed by the backend" with the signer, the responder, the starting block and the source URL as the backend gives it, then the editable fields. Use the shadcn components already in `components/ui`.
6. Beside the status line of the explorer page: "Indexed to block N" with the block time, and the state. `stopped` and a non-null `error` show as an alert with the backend's message.
7. `grep -rn` every removed name and variable over the repository, `agent-work/` aside, and leave no hit in code. README hits are step 05.3's: list them in your report.
8. Tests, with these titles:
   - `shows the server configuration read only`
   - `offers only the editable fields for editing`
   - `marks a network the backend does not serve`
   - `shows the indexed block and its time`
   - `shows a stopped network with the backend's reason`
   - `reads the MPC output cache with the server's signer address`

## Done when

`checks/04.7.sh` proves the six tests pass, no removed setting is left in the UI's code, and the repository checks pass.
