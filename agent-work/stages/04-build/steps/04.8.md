## Goal

Every way the ingest or the source could lose an event, store one twice, move the cursor past missing data or leak the token, found and marked `blocking` or `advisory`.

## Read first

- `agent-work/architecture.md` ("Ingest", O4, O5) and `agent-work/decisions.md` (D06, D12, D13, D23, and the three `gate` rows).
- `packages/backend/src/ingest/`, `packages/backend/src/source/`, `packages/backend/src/inspection/`, `packages/backend/src/db/`, whole.

## Work

You are given the code and the design. The builders' reports stay closed to you. Attack each heading, and write a line `covered: <heading>` in your report for each, with what you ran.

1. `atomicity`: find any path on which the cursor is written outside the transaction that stores its range, or the transaction commits with part of a range.
2. `interleavings`: two processes on one network, a crash between any two statements, a retry after a commit whose answer was lost. Write a test for each you can and run it against a PostgreSQL you start as `agent-work/lib/checks.sh` does (remove it after).
3. `the source`: paging by offset while new events arrive, a contract with more than one page in a range, an empty range, a range above the tip, an event whose block is outside the range, both roles at one address.
4. `the request rows`: can a `requests` row disagree with its events after any order of arrival or any retry?
5. `stopping`: does every identity mismatch stop before any write, and does a wipe followed by a cycle index again from the start block?
6. `secrets`: grep and read every log line, thrown message and stored `last_error` for a URL that could carry its query string.
7. `the checks`: does a test named in `checks/04.1.sh` or `checks/04.2.sh` pass without testing what its title says?

In `FINDINGS`, one line per finding, starting `blocking:` (the code does other than the design says, loses data, leaks a secret, or a check passes without the work) or `advisory:` (anything else). Continue a line by indenting. Write `none` when there is none. File your report first, then run the check.

## Done when

`checks/04.8.sh` proves the report covers the seven headings and marks every finding. It cannot prove a finding is right: the orchestrator reads the evidence beside each.
