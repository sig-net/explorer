## Goal

The explorer page lists `SignRequest` rows from the sign request service, one page at a time,
newest first, polled. Search, excluded callers and the state filter are queries to the service
and live in the URL beside `networkId`. The "Starting Block" control and the search back through
older blocks are gone from the page.

## Work

1. `lib/midnight/sign-request-search.ts`: the route's search parameters as one validated
   object: `requestId`, `search`, `excludeCallers`, `states`, and the page token. Each in
   canonical form, as the route does today for the two it has.
2. `components/midnight/sign-request-table.tsx` replaces the lifecycle table: the same columns
   in the same order, each cell rendered from the row's fields (first values and counts, as
   G15 settled: when a count is above one, the cell says how many more there are). The
   expanded row mounts the details component of step 04.9, which loads its own events from the
   network and the request id, through ONE prop, a render function `renderDetails(row)`, so
   that the table knows nothing of how details load. The route passes the real one.
   Delete the old table file and its test once nothing imports them, and move over every test
   case that still describes behaviour.
3. `routes/midnight/explorer.tsx`: read the page with `usePolledQuery` keyed on the network and
   the search object. A "newer" and an "older" control walk the pages by token. The search box
   is debounced into the URL. The excluded callers filter takes its candidates from
   `listCallers`. A state filter (`sign-request-state-filter.tsx`) sits in the filter panel.
   The status text gives the page's row count and the load's state. A linked `requestId` shows
   that one request, expanded.
4. Remove from the page: `SignetEventsStartingBlock`, the step back effect, the `searching`
   props and splash, `NoIndexerAlert`. In their place: no backend configured, the network not
   configured, the backend unreachable (with the error and a retry), each as an `Alert`.
5. Do not delete `MidnightSignetEventsContext`, the event store or their files: stage 05 does,
   when nothing uses them. After this step the page no longer calls `useMidnightSignetEvents`.
6. Tests with the fakes injected through `ExplorerBackendProvider`: the first page, walking to
   the last page and back, each filter changing the URL and the rows, a row whose state
   changes at the next poll, a linked request, and each of the three alerts.
7. `yarn lint`, `yarn build`, `yarn check`. Then build with `EXPLORER_BASE_PATH=/explorer/`
   and load the preview once: the request link a row copies must carry the base path. Commit.

## Done when

`checks/04.8.sh` proves the new table and filter exist, the page no longer uses the events
context or the starting block control, no cursor class was added, and all checks pass. It cannot
prove the page looks right: the orchestrator looks at it once in stage 05, against a backend.
