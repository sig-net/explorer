## Goal

`MidnightTransactionServiceImpl` serves a raw Midnight transaction and
`EthereumTransactionOutputServiceImpl` serves an EVM trace, each reading its table first and its
source second, and storing what the source gave. Neither can be used as an open proxy, and
neither ever stores a miss.

## Work

1. `services/midnight-transaction/midnight-transaction-service-impl.ts`: `getMidnightTransaction`
   refuses a hash that no stored event of that network carries (section 4.5), BEFORE touching
   the cache or the chain source. Otherwise: the cached row, else `rawTransaction` from the
   network's chain source, stored and returned. A chain source failure is reported and nothing
   is stored. Two calls at once for one hash end with one row.
2. `evm/evm-trace-source.ts`: an interface `EvmTraceSource` with one method that returns the
   top call frame of a mined transaction, or says the transaction is not mined or not known,
   or throws for a failure of the node. `evm/json-rpc-evm-trace-source.ts` implements it with
   `debug_traceTransaction` and the tracer options the UI uses, over a URL and a `fetch`. Its
   errors never hold the URL.
3. `services/ethereum-transaction-output/ethereum-transaction-output-service-impl.ts`: built
   from a map of chain id to `EvmTraceSource`. A chain with no source is refused with a message
   that names the chain id. Otherwise: the cached row, else the source. ONLY a frame of a mined
   transaction is stored. A miss, a pending transaction and a node failure are reported and
   never stored (section 4.6). What is stored and returned is the value G16 chose.
4. The backend returns no verdict (D02): the service does not decide whether a frame is
   "readable". If G16 chose the decoded output, it stores what the SDK decodes and reports the
   SDK's refusal as a refusal, in the reply's `error`.
5. Tests with the fake chain source, a hand-written `EvmTraceSource` and scratch databases: a
   hit, a miss that is then asked again and reaches the source again, the open proxy refusal,
   a failure that stores nothing, two calls at once, an unknown chain. For the JSON-RPC source,
   a scripted `fetch`: a frame, a JSON-RPC error, `null` for an unknown hash, a status 500.
6. One opt-in test, skipped unless `SEPOLIA_FORK_RPC_URL` is set: the JSON-RPC source reads
   the frame of a transaction of the latest finalised Sepolia block.
7. `yarn lint`, `yarn build`, `yarn check`, then the opt-in test once with the secret set
   through `dev-secrets get`. Commit.
