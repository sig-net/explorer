## Goal

The explorer page lists, searches, filters and pages lifecycles through an `ExplorerService` from `@sig-net/explorer-api`, and no code path of the list reads the indexer.

## Read first

- `agent-work/decisions.md`, D22, D37, D41 and D48.
- `packages/api/src/service.ts` (`ExplorerService`, `LifecyclesQuery`, `LifecyclePage`, `InspectedSignBidirectionalLifecycle`, `ExplorerApiError`, `LIFECYCLES_MIN_SEARCH_LENGTH`), `createExplorerApiClient` in `packages/api/src/client.ts`, and `createInMemoryExplorerService`, `explorerSeed` and `EXPLORER_SEED_CASES` of `@sig-net/explorer-api/testing`.
- `packages/ui/src/components/contexts/MidnightSignetEventsContext.tsx`, `packages/ui/src/routes/midnight/explorer.tsx`, `packages/ui/src/components/midnight/sign-bidirectional-lifecycle-table.tsx` and `excluded-callers-filter.tsx`, with their tests, and `packages/ui/src/lib/midnight/sign-bidirectional-lifecycle.ts`.

## Work

Change no manifest: the UI already depends on the api package.

1. `VITE_EXPLORER_API_URL`: declare it in `vite-env.d.ts`, list it in `parseRuntimeExplorerEnv` (`explorer-env.ts`), and parse it as an http or https URL in a new `packages/ui/src/lib/explorer-api.ts`, which builds the one client. Unset, the app still loads and the explorer page says no backend is configured.
2. `packages/ui/src/components/contexts/ExplorerApiContext.tsx`: provides the `ExplorerService`, or null when none is configured. The root mounts it with the client. Tests mount it with the in-memory service.
3. Replace `MidnightSignetEventsContext.tsx` with `MidnightLifecyclesContext.tsx`: for the selected network, the current `search` and `excludeCallers`, it holds the loaded pages (`InspectedSignBidirectionalLifecycle`, which the table takes as it is), the four counts of the newest answer, `status` (`loading`, `loaded`, `error`), `loadMore()` and `refresh()`. A change of network, search or exclusion starts again from the first page and drops answers of the earlier query. The search is debounced by 300 ms.
4. The page (`explorer.tsx`): search and exclusion go to the context and no longer filter in the browser. The status line keeps its form, `<matchingEvents>/<totalEvents> events, <matchingRequests>/<totalRequests> requests`, from the page's counts. Under the search box, while the fragment is shorter than `LIFECYCLES_MIN_SEARCH_LENGTH` and not empty: "Type at least 3 characters to search" (D41, the number from the constant). A linked `requestId` is read with `lifecycle(network, requestId)` and shown as the sole row, or "not found". An `ExplorerApiError` shows its message. Remove the starting block control and the step back loop.
5. The table gets a "Load more" row (a shadcn `Button`) while `nextBefore` is not null. Refresh re-reads the first page.
6. The excluded callers panel lists `callers(network)`.
7. Delete what nothing reads any more, with their tests: `signet-event-store.ts`, `signet-events-window.ts`, `indexer-block-height.ts`, `signet-events-starting-block.tsx`, and from `sign-bidirectional-lifecycle.ts` the four functions the page used to filter and count with (`...Matches`, `...CalledBy`, `...Callers`, `...EventCount`, D48). `grep -rn` each deleted name over the repository and leave no hit in `packages/ui`. Hits in `README.md` are step 05.3's: list them in your report. Leave `indexer-services.ts`, the inspection loader and the configuration popover to steps 04.6 and 04.7: an expanded row still inspects through the indexer until 04.6.
8. Tests, with these titles, over the in-memory service:
   - `lists the newest lifecycles of the selected network`
   - `load more appends the next page once`
   - `a search asks the service and resets the pages`
   - `a search shorter than three characters says so`
   - `shows the matching and total counts of the service`
   - `excluding a caller asks the service and keeps the URL in step`
   - `a linked request id shows that request alone`
   - `a linked request id that is unknown says so`
   - `refresh reads the first page again`
   - `a failing service shows the error and keeps what was loaded`
   - `without a backend URL the page says none is configured`
