## Goal

The explorer page lists, searches, filters and pages lifecycles through an `ExplorerService` from `@sig-net/explorer-api`, and no code path of the list reads the indexer.

## Read first

- `packages/api/src/`: `ExplorerService`, the lifecycle type it returns, `createExplorerApiClient`, and `@sig-net/explorer-api/testing`.
- `packages/ui/src/components/contexts/MidnightSignetEventsContext.tsx`, `packages/ui/src/routes/midnight/explorer.tsx`, `packages/ui/src/components/midnight/sign-bidirectional-lifecycle-table.tsx` and `excluded-callers-filter.tsx`, with their tests.

## Work

1. `VITE_EXPLORER_API_URL`: declare it in `vite-env.d.ts`, list it in `parseRuntimeExplorerEnv` (`explorer-env.ts`), and parse it as an http or https URL in a new `packages/ui/src/lib/explorer-api.ts`, which builds the one client. Unset, the app still loads and the explorer page says no backend is configured.
2. `packages/ui/src/components/contexts/ExplorerApiContext.tsx`: provides the `ExplorerService`. The root mounts it with the client. Tests mount it with the in-memory service.
3. Replace `MidnightSignetEventsContext.tsx` with `MidnightLifecyclesContext.tsx`: for the selected network, the current `search` and `excludeCallers`, it holds the loaded pages, the three counts, `status` (`loading`, `loaded`, `error`), `loadMore()` and `refresh()`. A change of network, search or exclusion starts again from the first page and drops answers of the earlier query. The search is debounced by 300 ms.
4. The page (`explorer.tsx`): search and exclusion go to the context and no longer filter in the browser. The status line shows matching and total requests and total events from the service. A linked `requestId` is read with `lifecycle(network, requestId)` and shown as the sole row, or "not found". Remove the starting block control and the step back loop.
5. The table gets a "Load more" row (a shadcn `Button`) while `nextBefore` is not null. Refresh re-reads the first page.
6. The excluded callers panel lists `callers(network)`.
7. Delete what nothing reads any more, with their tests: `signet-event-store.ts`, `signet-events-window.ts`, `indexer-block-height.ts`, `signet-events-starting-block.tsx`, and the browser-side search and filter helpers. `grep -rn` each deleted name over the repository and leave no hit outside `agent-work/`. Leave `indexer-services.ts`, the inspection loader and the configuration popover to steps 04.6 and 04.7.
8. Tests, with these titles, over the in-memory service:
   - `lists the newest lifecycles of the selected network`
   - `load more appends the next page once`
   - `a search asks the service and resets the pages`
   - `excluding a caller asks the service and keeps the URL in step`
   - `a linked request id shows that request alone`
   - `a linked request id that is unknown says so`
   - `refresh reads the first page again`
   - `a failing service shows the error and keeps what was loaded`
   - `without a backend URL the page says none is configured`

## Done when

`checks/04.5.sh` proves the nine tests exist and pass, the deleted modules are gone, and the repository checks pass. It cannot prove the page looks right: the orchestrator opens it in step 05.2's run.
