## Work

Change no manifest. The three defects, as the review reproduced each on a scratch PostgreSQL 17 at 60d5a3a:

- An event whose `name` holds U+0000 (`"Sign\u0000Event"`, which the SDK's name decoder can return) fails the cycle with `invalid byte sequence for encoding "UTF8": 0x00` on every retry, cursor unmoved.
- `recordedErrorText` cuts URLs over the whole text before it bounds it, and `textWithoutUrlCredentials` is quadratic on a run of `[a-z0-9+.-]`: a reason of 160,000 such characters held the process 11.6 s, on every retry.
- An inspection with a non-finite number (`length: NaN` in a cell's alignment) is stored with `null` in its place, the cycle answers `stored`, and `lifecycles()` and `lifecycle(id)` then reject with a ZodError. The same for an upper case hex atom and for a call chain 1000 deep (`Maximum call stack size exceeded` on read).

1. Every text the cycle stores from outside loses the characters the store refuses before it is stored (D52): an event's `name`, and the `stopped` reason, pass through the functions that already do this for an inspection's reasons. The event is stored and the cursor moves.
2. `recordedErrorText` strips the refused characters first, then cuts URLs, then bounds to 2000 characters, and takes under 100 ms for a text of 1,000,000 characters of any content. Bound the input before the cut in a way that leaves no credential in the result that the cut would have removed from the whole text: say in your report how. Make `textWithoutUrlCredentials` itself linear when that is a contained change, since the wire runs it on served texts.
3. A stored inspection is one the read path accepts: before it is stored, the value read back from its JSON is parsed with the schema the wire uses for a transaction's inspection (export from the api package what is needed, and census every user of what you export or change). One that does not parse is stored as `{ failed: <reason> }` for the whole transaction, as D52 does for a refused character.
4. Everything `storedInspectionJson` does to a result runs inside its guard: a result that cannot be serialised (a BigInt, a cycle, a chain too deep for the stack), an `undefined` or `null` result, a thrown value whose `String()` throws, and an Error whose message is not a string each give a stored `{ failed }` and a moved cursor.
5. Tests in the ingest's test file, with these titles:
   - `an event name holding a NUL character is stored without it`
   - `a failure text of a million characters is recorded within 100 ms`
   - `an inspection the wire rejects is stored as a failed inspection` (a non-finite number, an upper case hex atom and a call chain 1000 deep, and for each the page of the PostgreSQL service is served afterwards)
   - `an inspection that cannot be serialised is stored as a failed inspection`
   - `a NUL character inside a URL does not hide its credentials`
   Plant a fault for each and see it fail, restoring from a copy.
6. Every test that exists still passes.
