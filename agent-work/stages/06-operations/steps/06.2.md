## Goal

The three commands of section 9 exist and cannot be run by accident: `wipe` erases the database
and applies the shipped schema, `reset-network <network>` deletes one network's rows and nothing
else, and `schema-state` says whether the database holds the shipped schema. Starting the
backend still erases nothing, ever.

## Read first

- `../../../architecture.md`, sections 4 and 9. `../../../decisions.md`: D05, D06, D07.
- `packages/backend/src/commands/` (the table and the commands there), `src/db/schema.ts`,
  `src/db/schema-state.ts`, `src/db/migrate.ts`, `src/ingester/ingester.ts` (how the network's
  advisory lock is taken).

## Work

1. `schema-state`: prints `empty`, `current` or `mismatch`, exits 0 for `current` and 1
   otherwise. It reads only.
2. `wipe`: drops every object the backend's schema and the migrator made, then applies the
   shipped migration. It runs ONLY with the flag `--erase-everything` and prints, before it
   acts, the database's NAME and host (never the connection string) and the number of event
   rows about to be lost. Without the flag it prints what it would do and exits 1. It takes
   every network's advisory lock first and refuses while an ingester holds one.
3. `reset-network <network>`: in ONE transaction, deletes that network's rows from the events,
   sign requests, checkpoints, deployments and Midnight transactions tables. The Ethereum
   transaction outputs are keyed by chain and belong to no network: it leaves them. It takes
   the network's advisory lock and refuses while an ingester holds it. It needs the flag
   `--erase-network` and prints the row counts it is about to delete. After it, the next
   `start` begins that network at its configured start block.
4. Derive the list of tables a reset touches from the schema (every table with a `network_id`
   column), with a test that fails when a table is added and the reset does not cover it.
5. Register the three in the command table, add their scripts, and make an unknown command
   print the table's names and exit 1.
6. Tests on scratch databases with two networks' rows: `reset-network` removes exactly one
   network's rows from every table and leaves the other's and the Ethereum outputs. A reset
   under a held lock refuses. `wipe` without its flag changes nothing. `wipe` with it leaves
   `current` and no row. `schema-state` on the three states. After a reset, an ingester over
   the fake chain source starts at the start block and ends equal to before.
7. `yarn lint`, `yarn build`, `yarn check`. Commit.
