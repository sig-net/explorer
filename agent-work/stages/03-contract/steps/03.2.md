## Goal

`packages/api` exists as `@explorer/api`, and its `.` entry holds the whole contract in types:
for each of the four resources a zod schema, a service interface, an args schema per method and
the reply types, plus `deriveSignRequest`, the one rule that turns a request's events into its
row. Gates G15 and G16 are answered in the report.

## Read first

- The stage's `stage.md`, beside `steps/`: the conventions and the gates G15 and G16.
- `../../../architecture.md`: sections 4.3, 4.4 and 7, and the rule of section 1 that the
  backend returns no verdict.
- `agent-work/probes/findings/evm-trace.json`: the evidence of G11, for G16.
- `packages/ui/src/lib/midnight/sign-bidirectional-lifecycle.ts`: the grouping the aggregate
  must reproduce.

## Work

1. G15 first. From the `ui-census` pack and the table's source, list every value a list row
   shows and every filter the page applies, and beside each the column of 4.4 that answers it,
   or "none". Decide by the prepared answer in the gate table unless a filter cannot be
   answered. Put the table in your report under a line starting `CENSUS:`, and a line
   `COLUMNS ADDED: none` or the names. Decide G16 the same way, under `TRACE COLUMN:`.
2. Make the package as the `layout` pack says, with its three entries declared in
   `package.json` (`./http` and `./fakes` point at files the next two steps write), depending
   on `@explorer/lib` and `zod`. Folders and file names as the stage's conventions.
3. Resources, each field named exactly as its column in the architecture, in camelCase:
   - `SignetEvent`: the stored event of 4.3. `payload` is hex. `kind` is the closed set
     `decoded`, `unrecognised`, `undecodable`, defined once.
   - `SignRequest`: the row of 4.4, plus whatever G15 added. `state` is the closed set of four.
   - `MidnightNetworkStatus`: a union on `configured`. When true: the deployment (both
     addresses, root key, start block), the indexing status (`state`, `haltReason`,
     `processedBlock`, `processedBlockTime`, `headBlock`) and `indexerHost`. Never a URL (D21).
   - `MidnightTransaction` (`raw` as hex) and `EthereumTransactionOutput` (`chainId` as a
     decimal string, `trace` as G16 decided).
4. Service interfaces as section 7 lists them, methods returning domain values. Args:
   `listSignRequests` takes the network, an optional search fragment, excluded callers, states,
   a page size with a stated maximum, and an opaque page token, and returns the rows with the
   next page's token or none. `getSignRequest` returns the row with every event of the request
   in chain order. Reply types are `{ ok: true, ... } | { ok: false, error: string }`.
5. `deriveSignRequest(events)`: pure, from the stored events that declare one request id, in
   chain order, to the `SignRequest` row: the state rule of 4.4, first values, counts, sort
   keys, and a duration that may be negative. Table-driven tests cover every state, duplicates
   of each kind, a response before its request, and events that are not decoded (ignored).
6. Tests that each schema accepts a canonical value, rejects a `0x` prefix, upper case, a
   number where a decimal string belongs, and a reply holding a `url` key.
7. `yarn install`, commit the lockfile, then `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/03.2.sh` proves the package and its resource files exist, every column name of 4.3 and
4.4 is a field, the package imports no Fastify, Drizzle, React or Node module, the report holds
the three decision lines, and all checks pass. It cannot prove `deriveSignRequest` matches the
UI's grouping on real data: stage 05 compares them on preprod.
