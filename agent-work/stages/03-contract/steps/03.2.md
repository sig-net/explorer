## Goal

`packages/backend` holds the storage contract: SQL migrations that make one network's schema, Kysely types for its tables, the `lifecycle` view whose `events` column is in the wire shape, a wipe, and the `MidnightSource` port with an in-memory source for tests.

## Read first

- `agent-work/architecture.md`, "Ingest" and "Store", and "The wire" of the backend pack.
- `packages/api/src/wire.ts`: `lifecycleWireSchema` and `lifecycleFromWire`, which the view must satisfy.
- `packages/lib/src/midnight/signet-events.ts`: `StoredSignetMiscEvent` and the roles.

## Work

Every dependency is installed: change no manifest. Start a database for your own runs with `with_postgres` (backend pack).

1. `src/db/migrations/*.sql`, read from the folder beside the module (`import.meta.url`), applied in name order inside a schema named `midnight_<network>` (D18), recorded in a `migrations` table of that schema, each in its own transaction. `migrateNetworkSchema(db, network)` is idempotent and safe when two processes start together (an advisory lock keyed on the schema name).
2. Tables:
   - `ingest_state`, one row at most: `genesis_hash`, `signer_address`, `responder_address`, `start_block`, `cursor_height`, `cursor_hash`, `cursor_block_time`, `tip_height`, `state`, `last_success_at`, `last_error`.
   - `transactions`: `hash` primary key, `block_height`, `block_hash`, `block_time`, `raw` (nullable, D26), `inspection` jsonb (D34, null for a transaction that was not inspected).
   - `events`: `id` bigint primary key (the indexer's), `transaction_hash` references `transactions`, `contract_roles` text[], `name`, `payload` bytea, `request_id` (null when the event did not decode), `decode_failure` (null when it decoded or was not a Signet name).
   - `requests`: `request_id` primary key, `first_event_id`, `caller` (null until a notification names one), `first_requested_at`, `first_signature_at`, `first_response_at`, and a count per event kind.
   Indexes: `events (request_id, id)`, `requests (first_event_id DESC)`, trigram (`pg_trgm`, `gin_trgm_ops`) on `requests.request_id` and `requests.caller`. The extension is created in the `public` schema, once.
3. The view `lifecycle`: every column of `requests` plus `events`, a JSON array in emission order holding each event exactly as the wire's event (camelCase keys, `payload` as hex, `blockTime` as the backend pack says). A sign bidirectional event carries `inspection`: `{ callChains, requestCell }` with the cell `requestCells` holds under the event's own id, or `{ failed }`, and `{ "failed": "not inspected" }` when the transaction's column is null. One row of the view is one row of the list (O6).
4. `wipeNetworkSchema(db, network)` drops that schema and nothing else.
5. `src/db/schema.ts`: the Kysely table interfaces, and `networkDb(db, network)` that returns a Kysely instance bound to the schema (`withSchema`).
6. `src/db/testing.ts`: `createTestDatabase()` makes a database with a random name inside `EXPLORER_TEST_DATABASE_URL` and returns it with a `drop()`. It throws when the variable is unset.
7. `src/source/port.ts`, the `MidnightSource` interface: `genesisHash()`, `finalisedTip()` (height, hash, time), `blockAt(height)` (hash and time, null above the tip), `eventsIn({ fromBlock, toBlock })` (the events of both contracts as `StoredSignetMiscEvent` with their roles, ascending by id), `rawTransaction(hash)` (hex). `src/source/in-memory.ts`: a source over a list of blocks that a test can extend, make fail on the next call, or replace a block of.
8. Tests, which seed their rows with SQL, with these titles:
   - `migrating twice changes nothing`
   - `two networks get separate schemas`
   - `wiping one network leaves the other untouched`
   - `a lifecycle view row satisfies the wire schema` (parse `{ requestId, firstEventId, events }` of a row with `lifecycleWireSchema`, decode it with `lifecycleFromWire`, and compare with the events seeded)
   - `the view gives each request of one transaction its own record` (two sign bidirectional events in one transaction, two cells)
   - `the view lists a response that has no request`
   - `the list query reads no table in full` (seed 20,000 requests with `generate_series`, `ANALYZE`, `EXPLAIN` the newest 50 with their events, assert no `Seq Scan`. Give the test a timeout of its own)
   - `the in-memory source serves a range in emission order`

## Done when

`checks/03.2.sh` proves the eight tests exist and pass against a real PostgreSQL, fail without one, and the repository checks pass. It cannot prove the schema loses nothing the UI needs: review 03.3 attacks that.
