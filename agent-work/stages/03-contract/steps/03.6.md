## Goal

The contract of stage 03 has been attacked by someone who did not write it, and every finding
is marked `blocking` or `advisory`. You change no file. You read the code, not the builders'
reports: do not open anything under `agent-work/reports/`.

## Work

Attack these, in this order, and write down for each what you ran or read:

1. The schema against section 4: every table, column, type, nullability, key and index. A
   column the design names that is missing, or one it does not name, is a finding. The primary
   key of events is the chain position, never the indexer's id.
2. The resources against the schema: every column is a field of the same name, and the wire
   form of each (hex, ISO time, number, decimal string) is the one the stage fixed.
3. Facts and no verdicts (D02): no field of any resource states that a signature, an
   attestation or a transaction is valid. `state` names what was declared.
4. Secrets (D21): no reply type can carry a URL. Try to make the fake network service return
   an indexer URL through the types: if the compiler lets you, that is a finding.
5. `deriveSignRequest` against the table of states in 4.4 and against the UI's grouping in
   `packages/ui/src/lib/midnight/sign-bidirectional-lifecycle.ts`: write five event sequences
   of your own, hard ones, and run both by hand or in a scratch test you do not commit.
6. The list against the census: can every filter and every column of today's page be answered
   by `listSignRequests` and `listCallers` as typed? Is the order total, so that keyset paging
   neither skips nor repeats a row when two requests share a first block?
7. The chain source seam: can the fake script every failure section 5 names (a range that
   keeps failing, a changed hash under the checkpoint, a late event, a different answer on
   re-read, a crash between read and commit)? Can a node-reading implementation satisfy the
   interface without the indexer's event id?
8. The transport: a method of an interface with no route, a reply the client accepts and the
   schema should refuse, an adaptor that throws on bad input.
9. The packages' reach: `lib` and `api` import nothing Node-only, `api` imports nothing of
   `backend`, and the UI's build still holds two WebAssembly files (`yarn build`, then look).

File your report FIRST, then run the exit check. In `FINDINGS`, each finding is one line
starting `FINDING <n> (blocking): ` or `FINDING <n> (advisory): `, with the file and line and
what you ran. `blocking` means: the code does other than the design says, loses data, leaks a
secret, or a check passes without the work. Everything else is `advisory`: a missing test for a
case the design does not state, a question, a matter of style. With no finding at all, write the
line `NO FINDINGS`. Add one line `ATTACKED: ` listing which of the nine items you completed.
