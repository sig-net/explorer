## Goal

`@sig-net/explorer-api` is the whole HTTP contract (D20): zod wire schemas, the `ExplorerService` interface, a fetch client that implements it, a Hono routes adaptor that serves it, and an in-memory service with fixtures that the UI and the server shell are built against.

## Read first

- `packages/lib/src/index.ts` and the modules it exports.
- `packages/ui/src/lib/midnight/sign-bidirectional-transaction-inspection.ts`: `ContractCallNode`, `SignBidirectionalTransactionInspection`, and where the request record is decoded from a cell (`decodeEvmType2SignBidirectionalEvent`).
- `packages/ui/src/routes/midnight/explorer.tsx`: what the list page shows and filters by.

## Work

1. `ExplorerService`, every method async:
   - `networks()`: for each served network, `network`, `config` (`signerContractAddress`, `responderContractAddress`, `startBlock`, `sourceUrl` with no query string) and `sync` (`state`: `starting`, `syncing`, `synced` or `stopped`, `processedBlock`, `processedBlockTime`, `tipBlock`, `lastSuccessAt`, `error`, each null until known).
   - `lifecycles(network, { search?, excludeCallers?, before?, limit? })`: `lifecycles` newest first, `nextBefore` (the cursor of the next page, null at the end), `matchingRequests`, `totalRequests`, `totalEvents`. `limit` defaults to 50, at most 200. `search` is a fragment of a request id or caller, case-insensitive, optional `0x`.
   - `lifecycle(network, requestId)`: one lifecycle, or null.
   - `callers(network)`: the distinct caller addresses.
   An unknown network is a typed error, never an empty answer.
2. The domain type a lifecycle is returned as: lib's `SignBidirectionalLifecycle`, extended so that each sign bidirectional event carries its transaction's inspection, which is one of: `{ callChains, request }`, `{ failed: reason }`. Define this type here and export it.
3. The wire, as zod schemas. An event crosses as its stored source: `id`, `name`, `payload` (hex), `transactionHash`, `blockHeight`, `blockHash`, `blockTime`, `roles`. The client rebuilds the decoded event with lib's `decodeSignetContractEvent`, so no record codec exists. The request record crosses as the cell the transcript wrote (an `AlignedValue`: atoms as hex, the alignment as JSON), and the client decodes it with `decodeEvmType2SignBidirectionalEvent`. Test the round trip with the lib fixture first: see the stage's gate for the fallback.
4. Routes under `/v1`: `GET /networks`, `GET /networks/:network/lifecycles`, `GET /networks/:network/lifecycles/:requestId`, `GET /networks/:network/callers`. Errors are `{ error: { code, message } }` with `code` one of `not_found`, `invalid_request`, `unavailable`, and status 404, 400, 503. `explorerApiRoutes(service)` returns a Hono app. It adds no CORS and no health route: the backend owns those.
5. `createExplorerApiClient({ baseUrl, fetch? })` returns an `ExplorerService`. It validates every response with the schemas and throws a typed error for an error body or a body that does not validate.
6. `createInMemoryExplorerService(seed)` under a second entry, `@sig-net/explorer-api/testing`: it holds stored events and inspections per network and answers with the same search, exclusion and paging rules, built on lib's `aggregateSignBidirectionalLifecycles`. Export a seed with at least: a complete lifecycle, one with a response and no request, one with two requests, one whose inspection failed.
7. Tests, with these titles:
   - `round trips every event kind through the wire`
   - `round trips the request record through the wire`
   - `client and routes agree over the in-memory service`
   - `pages newest first without repeating or skipping a lifecycle`
   - `searches by a fragment of a request id or a caller`
   - `excludes callers`
   - `answers 404 for an unknown network and an unknown request`
   - `answers 400 for an invalid query`
   - `the client rejects a body that does not validate`
   - `the source url carries no query string`

`checks/03.1.sh` proves the ten tests exist and pass, both entries resolve from Node, and the repository checks pass. It cannot prove the contract serves everything the UI shows: review 03.3 attacks that.
