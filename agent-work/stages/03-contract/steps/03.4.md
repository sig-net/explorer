## Goal

The `./fakes` entry of `@explorer/api` holds an in-memory implementation of each of the four
service interfaces over a fixture history of stored events, good enough that stage 04 builds and
tests the whole UI against it: paging, search, exclusion, state filter, a halted network, a
network that is not configured, a raw transaction and a trace.

## Read first

- The stage's `stage.md`, beside `steps/`: the conventions.
- Every `packages/api/src/*/*-service.ts` and `packages/api/src/sign-request/derive-sign-request.ts`.
- `packages/ui/src/lib/midnight/sign-bidirectional-event.fixture.ts`,
  `respond-bidirectional-event.fixture.ts` and `sign-bidirectional-lifecycle.fixture.ts`: how
  the UI's tests build events whose signatures and attestations verify. Build yours the same
  way. Do not import from `packages/ui`, and do not move those files: the UI's steps of stage
  04 decide what becomes of them.
- `node_modules/@sig-net/midnight/dist/testing.d.ts`: the SDK's helpers for minting records.

## Work

1. `src/fakes/signet-history.ts`: a function that builds a history of `SignetEvent`s for one
   network, deterministic, with at least: 30 requests so that a list has several pages. A
   request in each of the four states. A request with two notifications from two callers. A
   request with two signature responses of which one verifies. A response in an earlier block
   than its request. One `unrecognised` and one `undecodable` event. At least three distinct
   callers. Payloads are the 256-byte form the SDK normalises to, as hex.
2. `src/fakes/sign-request-service-fake.ts`: over a history, rows come from `deriveSignRequest`, never
   from a second copy of its rule. `listSignRequests` orders newest first by the sort key,
   pages by keyset with an opaque token, and applies the search fragment (request id or caller,
   case-insensitive, optional `0x`), the excluded callers and the states, exactly as the args'
   documentation says. `getSignRequest` returns the row and its events in chain order.
   `listCallers` returns the distinct callers. It exposes one method beyond the interface,
   `append(events)`, so a test can make a row change between two polls.
3. `src/fakes/network-service-fake.ts`: built from a list of statuses, with helpers for a running
   network, a halted one with a reason, and one that is not configured.
4. `src/fakes/midnight-transaction-service-fake.ts`: serves raw bytes for the hashes it is
   given and refuses every other hash. `src/fakes/ethereum-transaction-output-service-fake.ts`: serves the traces
   it is given by chain id and hash and refuses the rest.
5. Tests for each fake: every filter alone and combined, a walk through all pages that sees
   every row once, a row whose state changes after `append`, and the refusals.
6. `src/fakes.ts` exports the fakes and the fixture builders. Do not touch `src/index.ts`,
   `src/http.ts` or `package.json`. `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/03.4.sh` proves the four fakes and the fixture file exist with their tests, the sign
request fake calls `deriveSignRequest`, the entry imports under Node, and all checks pass. It
cannot prove the fixtures' signatures verify: the fake's own test checks one with the SDK, and
the orchestrator confirms that test exists by name in the report.
