## Goal

`packages/backend` holds what stage 04's backend steps build against, each in its own folder:
the Drizzle schema of the six tables with its ONE generated migration and a way to tell whether
a database holds exactly that schema, the `MidnightChainSource` interface with a scriptable fake,
and the repository and unit of work interfaces.

## Read first

- `../../../architecture.md`: sections 4, 5, 6 and 9.
- `../../../decisions.md`: the outcomes of G01, G02, G15 and G16.
- `packages/api/src/sign-request/signet-event.ts`, `sign-request.ts` and the other three
  resource files: column properties are named exactly as their fields.
- In the demo checkout the `backend-patterns` pack names: `src/lib/db/schema.ts:255-275,505-517`,
  `drizzle.config.ts`, `package.json:20-21`, `scripts/migrate.ts`,
  `src/lib/repository/repository.ts:6-39`, `src/lib/db/unit-of-work.ts:11-50`.

## Work

1. Add `@explorer/lib` and `@explorer/api` to the package as `workspace:*`. `yarn install` and
   commit the lockfile. You are the only step of this stage's parallel three that may.
2. `src/db/schema.ts`: the six tables of section 4, names ending `_v1`, every column, key and
   index as written there, plus what G15 added. `network_id` first in every key. Closed sets
   come from `@explorer/api` only if that import survives drizzle-kit's CommonJS loader (the
   pack's warning): if it does not, say so in the report and import the set from a file with no
   SDK import. 64-bit columns read as the type the resource's field has.
3. `drizzle.config.ts` and the script `db:generate`: delete `drizzle/`, generate ONE migration
   named `schema`, and put `create extension if not exists pg_trgm` ahead of the first table.
   Commit `drizzle/`. `src/db/migrate.ts`: `migrate(database)` applies it with drizzle-orm's
   migrator, and the script `db:migrate` runs it on `DB_CONNECTION_STRING` through plain Node.
4. `src/db/schema-state.ts`: `readSchemaState(database)` answers `empty` (no migration table),
   `current` (exactly the shipped migration is applied, by the hash the migrator records) or
   `mismatch`. It reads and never writes. This is what the start-up refusal and the wipe
   command of later stages stand on.
5. Make the scratch database harness apply the migration.
6. `src/chain-source/chain-source.ts`: `MidnightChainSource` exactly as section 6, with
   `BlockRef`, `BlockRange` (inclusive at both ends), `SignetContracts` and `ChainSignetEvent`
   (the chain facts of 4.3: position, block, transaction, emitter and its roles, the indexer's
   id, name, payload). Document on each method what "complete or throws" means for it.
7. `src/chain-source/fake-chain-source.ts`: a chain a test scripts. It can add blocks with
   events and advance the head, replace a block at or below the head with another hash, hold an
   event back so that it appears only after the head has passed its block, fail the next N
   calls of a method, and answer a range differently on a later read. Test each ability.
8. `src/repositories/`: one interface file per table, in the demo's vocabulary over this
   task's keys, with the methods section 5's loop and section 7's services need and no others,
   and `unit-of-work.ts` with the `runInTransaction` contract. Interfaces only. Beside them,
   `src/logging/`: the `Logger` port, its pino implementation and a recording logger for
   tests, shaped as the demo's (`src/lib/logging/` there), because every class of stage 04
   takes a logger.
9. `src/db/schema.test.ts`, on a scratch database: a row of every table goes in and comes out
   equal. A second insert at an existing key fails. `readSchemaState` answers `empty`, then
   `current`, then `mismatch` after `alter table ... add column`. A test regenerates the
   migration into a temporary folder and compares it with the committed one, and asserts
   `drizzle/` holds exactly one `.sql` file.
10. `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/03.5.sh` proves the six tables and their indexes exist in a database the migration
built, `drizzle/` holds one migration that a fresh generation reproduces, the chain source,
its fake and the repository interfaces exist, and all checks pass. It cannot prove the fake can
script every failure stage 04 needs: 03.6 attacks that.
