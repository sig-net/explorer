## Goal

The `./http` entry of `@explorer/api` holds the transport half of the contract: one route table,
one adaptor per service that turns unknown input into a reply, and one HTTP client per service
that implements the service's interface over `fetch`. A test sends every method of every service
through client, route and adaptor and gets the same value back.

## Read first

- The stage's `stage.md`, beside `steps/`: the conventions (route names, the wire forms).
- `../../../architecture.md`, section 7.
- Every `packages/api/src/*/*-service.ts`: the interfaces, args schemas and reply types.
- In the demo checkout the `backend-patterns` pack names:
  `src/lib/midnight/ethereum-erc20-vault/approval-v1/approval-service-adaptor.ts:31-60`.

## Work

1. `src/http/routes.ts`: the route table, one entry per method of the four services: the
   path, the args schema and the reply schema. Type it so that a method missing from the table,
   or present with another method's schemas, does not compile.
2. One `src/http/<resource>-service-adaptor.ts` per service: a class over the service interface. Each
   method takes `args: unknown`, validates with the args schema, and returns the reply type:
   `{ ok: false, error: z.prettifyError(...) }` for bad input, `{ ok: true, ... }` otherwise.
   An absent resource is `ok: false` with a message, never an exception. An exception from the
   service is NOT caught here: the host decides what a failure looks like.
3. `src/http/mount.ts`: `mountRoutes(adaptors)` returns, for each route, its path and a
   function from the parsed JSON body to the reply. It knows nothing of Fastify: the backend's
   host registers what this returns.
4. One `src/http/<resource>-http-client.ts` per service: a class that implements the service interface
   over `fetch(baseUrl + path)`, POST with a JSON body. It validates the reply with the reply
   schema, returns the domain value of `ok: true`, and throws one error type,
   `ServiceError`, carrying the reply's message for `ok: false`, and a distinct
   `TransportError` for a network failure, a status that is not 200 or a reply that fails its
   schema. The constructor takes the base URL and, for tests, the `fetch` to use.
5. `src/http/loopback.test.ts`: a `fetch` that routes a request through `mountRoutes` over
   hand-written services, with no socket. For every method: the value the service returns is
   the value the client returns, with bytes, times and decimal strings surviving the wire. Bad
   args give `ServiceError`. A reply with a missing field gives `TransportError`.
6. `src/http.ts` exports the table, `mountRoutes`, the adaptors, the clients and the two error
   types. Do not touch `src/index.ts` or `package.json`: both are another step's.
7. `yarn lint`, `yarn build`, `yarn check`. Commit.

## Done when

`checks/03.3.sh` proves the files exist for all four services, the loopback test is there and
passes inside `yarn check`, nothing in the package imports Fastify, and Node imports the entry
from source. It cannot prove the table's types really reject a missing method: the orchestrator
deletes one entry and watches `yarn typecheck` fail.
